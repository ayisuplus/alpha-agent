# 三栏工作台重构（2026-09-24）

上一版工作台的问题在结构：Electron 把窗口固定切成左 44%（限 500–650px）和右侧预览，左栏里又放了 174px 任务列表，工作区只剩约 330–480px；约 10 张同样式卡片纵向堆叠，三个输入框语义重叠，“任务过程”和“本次实时事件”重复展示同一事件流；证据是平铺的长字符串，源码改动是两整份文件并排。代码是一个 447 行组件、约 30 个 `useState`，WebSocket 之外每 5 秒轮询 4 个接口，断线不重连。

## 现在的结构

- **窗口**：shell 视图铺满窗口，界面上报预览槽位置（`alpha:preview-bounds`），主进程把原生预览视图放到该位置；无在线预览时给空边界隐藏。实测 `View.setVisible(true)` 无法让先隐藏的视图重新显示，因此用边界控制。默认菜单栏自动隐藏（Alt 可唤出）。
- **左栏**：任务按运行中 / 今天 / 昨天 / 更早分组，标题取 v1 目标首句并去掉“制作一个本地可用的”“Build a small”这类开头；可折叠为窄条。
- **中栏**：头部是标题、目标版本（可展开历史）、状态、验收项标签和最近问题；时间线一轮一个回合，模型文字按 Markdown 渲染（链接不跳转、不加载图片），连续工具调用折叠成摘要，展开可见路径与 intent，阶段 / 构建 / 浏览器结果以步骤列表呈现并可跳到对应证据，回合末尾链接到该轮源码 diff；运行中补充的要求插在对应回合里并带投递状态。证据视图按验收项分页，浏览器步骤编号沿用验收器的 1 起始编号（修正了旧版多加 1），失败步骤单独解析；diff 视图为统一格式、带行号与增删统计。底部只有一个输入框，按状态切换为开始构建、运行中补充（附停止）、继续修复 / 仅保存到下轮、修订目标。
- **右栏**：工具栏显示在线状态、地址、接管 / 交回 Alpha、重新验收；无在线预览时显示原因和“重新发布并验收”。分隔条可拖动（双击复位），宽度比例保存在本机。运行中的任务独占预览，切换任务不会打断验收。
- **代码**：`desktop/ui/src` 分为 `api/`（类型、接口封装与中文错误、带重连的事件流）、`state/`（单一 store 与纯函数：时间线、证据解析、diff、标签）和 `components/`。时间线、证据解析、diff 与标题提取有单元测试。

## 内核附加改动（只增加字段，流程未变）

- `omp-runner.ts` 转发 OMP 已有的 `toolCallId`、`intent` 和展示用目标（项目相对路径、搜索模式等；不转发文件内容）。
- `task-activity.ts` 拆出同步的 `create` 与 `write`；活动条目增加可选的 `callId`、`target`、`intent`、`error`。
- `server.ts` 在写入前通过 WebSocket 广播 `{type:"activity"}`，界面以它为时间线唯一来源并按 id 去重；任务摘要和详情增加 `originalObjective` 与 `createdAt`。

## 验证

`bun run check`、`bun run test`（43 项，新增 `test/workbench-timeline.test.ts`，并在 `task-workbench.test.ts` 中验证活动字段往返与 WebSocket 广播）和 `bun run build:desktop-ui` 通过。

用 `release/.alpha` 与 `.alpha/ui-workbench-probe` 的数据副本（路径改写到隔离目录，原数据只读）启动 sidecar 与桌面端，检查了新旧任务的时间线、证据视图、diff 视图、新建任务页与各输入模式。在食谱收藏副本上点“重新发布并验收”，真实构建、发布，并通过 CDP 在停靠的预览视图上完成浏览器验收，任务回到已验收；原生预览与槽位完全重合，拖动分隔条时光标越过原生视图仍能继续拖动，预览随之调整；接管 / 交回经服务端往返。没有运行新的模型任务，所以运行中的流式文字、带路径的工具行和运行中补充要求只由单元测试和活动数据回放覆盖，尚未在真实模型运行中查看。现有便携包早于本次改动，需要重新执行 `bun run package:portable`。
