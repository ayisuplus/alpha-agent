# Alpha 与 ZCode：桌面产品成熟度差距与补齐顺序

日期：2026-09-30。范围：产品体验、视觉体系和桌面交互。本轮只形成评估与实施建议，未修改产品代码。

## 1. 结论与证据边界

Alpha 已经有个人 agent 工作台的主要能力入口。当前最值得投入的是统一输入与阅读体验、呈现执行状态、串联结果交付，以及建立可持续执行的组件规范。这些工作可以在现有 OMP 内核和天枢证据扩展上完成。

本轮依据：

- Alpha 当前源码：`ef9d3b0a9cab6871a1dd835ff2e63c07ee5f4bf6`，package 版本 0.2.1。包括发行后追加的右栏、首页工具栏与文件预览改动；不能与原 0.2.1 安装包直接等同。
- 已查看本机既有验收截图：`artifacts/home-toolbar-2026-09-30/home.png`、`artifacts/right-workspace-2026-09-30/review.png`。截图用于观察布局，拍摄于本轮之前，不能充当本轮完整实机验收。
- ZCode 公共源码固定到 `29628c9acdb81b703bbd4080c207a0e7ce5e276e`；抽查设计规范、输入组件、草稿存储、会话滚动、附件状态、错误归因、待处理命令恢复及基础组件。
- 在内置浏览器查看 [ZCode 官网](https://zcode.z.ai/cn)的交互式工作台演示。它是官方展示，不等同于运行桌面发行版。官网更新日志列出 2026-09-29 发布的 3.14.4，仓库 README 则标注 3.14.3；两者分别记录。
- 未安装或运行 ZCode，未比较双方模型能力、任务成功率、性能或长期稳定性。公开实现说明它关注了哪些细节，不证明全部无缺陷。

当前视觉判断：Alpha 的暖纸色、墨色操作与植物半色调开场值得保留。成熟度差距更多来自控件与操作规律不统一、工作状态组织偏弱，以及用户需要理解过多技术信息。内核强弱需要另设基准，本报告不作排名。

| 输入区一致性 | 首页用可搜索 `NativeModelPicker`、Ctrl+Enter；会话页用原生 select、Enter；首页没有对应附件入口；会话页把模型设置、压缩上下文和原生命令平铺 | [ConversationComposer](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/ui/src/v4/ConversationComposer.tsx)与 composer 子目录；官网演示集中呈现上下文、模型与发送 | 共享一个输入组件与发送规则；附件、模型、思考强度位置稳定；低频命令进入更多菜单；首次使用即可带材料开始 |

## 3. 应先修的具体细节

以下是当前源码直接支持的发现，不是本轮桌面交互复现记录。实施时先补对应行为回归，再修改。

### 3.1 自动滚动未接线

`NativeThread.tsx:307` 声明 `end` ref，312 行调用 `scrollIntoView`，但返回的 JSX 没有任何 `ref={end}`。这条自动滚动路径实际没有目标节点；依赖 `items.length` 也不能覆盖同一消息持续增长的场景。

验收：流式长回答持续跟随；用户上翻后不被拖回底部；点击“回到最新”恢复跟随；切换会话不串位置。应把锚点放在真实消息滚动容器内。

### 3.2 会话草稿在卸载后丢失

`NativeThread.tsx:218` 起的 Composer 将草稿放在组件内 `Map`；`NativeApp.tsx` 切到设置或首页时会卸载会话界面。首页有 localStorage 草稿，会话页未做相同持久化。

验收：输入未发送内容后，打开设置再返回、返回首页再进入、刷新应用，正文仍在且归属正确。附件先明确生命周期，不能将过期 File/object URL 当作可恢复文件。ZCode 的 [v4 草稿实现](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/ui/src/v4/composer/composerDraftStore.ts)也明确没有持久化附件，不应误读为它已解决所有附件恢复问题。

### 3.3 仅图片不能发送

`NativeThread.tsx:285` 的发送按钮只考虑正文和文件路径，没有考虑 `image`；`useSession.ts` 的 send 又要求非空文字。选图但不输入文字无法提交。

验收：根据模型的真实图片能力支持仅图输入，或明确提示必须补充文字；禁止留下一个无说明的禁用按钮。图片失败应保留草稿并允许重试。

### 3.4 首页与会话的发送规则不同

首页 Ctrl+Enter，会话 Enter，虽各自有实现，跨页面仍会改变操作预期。统一共享输入组件时确定一套默认规则，并保留 Shift+Enter 换行与中文输入法组合输入保护。

验收：首页、空会话、已运行会话遵循同一规则；中文选词回车不发送；等待回执期间重复点击不重复创建任务。

### 3.5 弹窗缺少完整焦点管理

`NativeDialogs.tsx` 使用 div 与 `role=dialog`，没有焦点约束、关闭后焦点返回或统一 Escape 取消行为。仅加 ARIA 属性不能替代键盘交互。

验收：Tab 在当前模态内循环；打开后聚焦合理；关闭后回到触发按钮；Escape 对应取消而非确认；后端已取消的请求不能继续提交。ZCode 的 [Dialog](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/ui/src/components/ui/dialog.tsx)基于 Radix，可以借鉴其组件契约，是否引入依赖单独评估。

## 4. 视觉与交互方向

保留 Alpha 当前的品牌资产：暖白底、墨色主要操作、低饱和植物绿和开场问候。以 ZCode 的真实工作台展示、设计规范和组件为参照，建立 Alpha 自己的规则。

建议先定五件事：

1. **字体角色**：界面正文约 14px、次要信息约 12px、重要标题单独一级；现有大量 10–11px 的常用控制文字应重新核对可读性。展示字体集中在欢迎问候，工作区文字使用易读的 UI 字体。具体值须用真实中文内容和 Windows 缩放验收。
2. **控件与间距**：沿用现有 4px 间距基准，统一常用 32/36px 控件高度和图标按钮触达面积。避免每个页面自定圆角、边距和按钮形状。
3. **层级**：侧栏承担导航，中间承担对话，右栏承担当前结果与上下文。重命名/导出/归档等低频操作收进更多菜单；运行状态、等待输入和停止操作保持易见。
4. **渐进展开**：默认显示执行摘要、结果和下一步动作；工具参数、日志、完整路径、哈希进入可展开详情，保留可追溯能力。
5. **空间适应**：右栏增加可拖动宽度与记忆；较窄窗口保持覆盖面板入口；工具栏允许有规则地收纳。深色与跟随系统主题放在 token 和组件稳定之后。

第一轮可审阅设计范围控制为：有材料的新任务、工具执行中的会话、产物预览、需要用户处理的异常。使用真实名称、长路径和已有 Office/媒体产物，避免只做空白首页。

## 5. 分阶段实施与验收

| 顺序 | 交付范围 | 验收标准 |
| --- | --- | --- |
| A：高频交互修复 | 草稿保存、滚动跟随、仅图发送规则、中文输入法与统一发送行为、弹窗焦点；按实际操作补浏览器回归 | 打开设置不丢草稿；上翻阅读不跳位；带附件任务能完成提交；键盘可完成一次模型选择和确认/取消；错误后能继续 |
| B：统一工作台体验 | 基础组件与 token 落实；共享输入区；工具执行摘要；产物打开右栏；文件级差异视图；就地恢复提示 | 新建→补充材料→执行→等待用户→查看产物→继续修改的主流程连贯；同类控件外观与行为一致；长中文、长路径不挤掉操作 |
| C：持续使用体验 | cwd 项目分组、置顶/未读、面板宽度记忆、Skill 使用入口、常用快捷键；视需要补深色主题 | 会话数量增多后仍能定位运行中和待处理任务；重启后个人界面偏好保留；用户能发现并使用 Skill，而非只看到目录清单 |

A 与 B 可以在同一体验版本中逐步交付，每步保留截图与行为回归，避免同时改掉所有页面后才发现问题。优先级依据是用户遇到频率、丢失输入的风险及对主流程的影响；不以对方功能数量排序。本轮没有估算工期，需在确认实施范围后评估。

## 6. 实现边界

- OMP 继续负责执行、会话、模型与原生工具；天枢继续提供证据建议。UI 只消费现有事件与命令，新增展示状态不成为第二套执行状态来源。
- 共用输入组件直接复用现有模型目录、账号配置和原生命令；不新建模型白名单或专家调度层。
- 执行摘要由真实工具事件导出。没有阶段、耗时、百分比或验证结果的数据时，不生成虚构进度。
- “结果打开右栏”优先连接现有产物契约与文件预览 API；项目 Git diff 继续明确显示范围。逐文件撤销需要可靠的归属和恢复机制，不能把整个工作区的改动都认作当前任务。
- 原有 Office/媒体生成、预览、浏览器接管能力继续保留；Alpha 的定位允许把文档、图片、音视频交付放在更显眼的位置。ZCode 已有 Office/PDF/媒体能力，不能宣称这类功能为 Alpha 独有。
- 此阶段不迁移 ZCode 内核，不整体引入其 monorepo、商业账号/套餐、Bot/远程服务或工作流系统。若后续直接复用代码，按对应文件许可证和第三方声明记录来源；品牌素材不直接沿用。

## 7. 验证计划与本轮交付

现有 `native-ui-contract` 测试覆盖消息组装与 UI 帧等函数契约，不能证明滚动、草稿生命周期、焦点、Windows 缩放或最终审美通过。后续需要少量覆盖真实操作的浏览器测试与人工审阅：

- 首页、执行、等待输入、失败、完成、恢复六种状态各留一张真实截图。
- 1366×768、1920×1080、窄窗口，以及 Windows 125%/150% 缩放验证主要控件可达。
- 带长路径、长表格、长工具输出、中文输入法和多会话的场景；测量后再决定列表虚拟化等优化。
- 一个代码改动任务与一个真实 Office/媒体交付任务，验证预览和继续修改的完整路径；自动检查与人工视觉认可分别记录。

本轮只新增本报告。下载的 ZCode 源码样本位于系统临时目录，未写入 Alpha 依赖、未运行其代码。初始 `reference/oh-my-pi` 脏状态与 `.tmp-host-window.png` 保留；参考子仓库 HEAD 为 `73a11421fe34fbab8ad058ab9c1a2e4f447852ea`。
