# 核心专家精简与验收

本轮目标是精简专家和提升可用性，沿用现有 TaskLedger、主/子代理责任、能力池、权限和不可变快照机制。

## 现状与标准

整理前，当前 `.alpha/agent-presets.json` 有 94 个启用专家，均来自本地 WorkBuddy 导入；其中 55 个没有随包 Skill，39 个虽有 Skill，仍需排查重复职责和平台专属依赖。没有 Skill 的人设不能满足本轮核心专家标准。

人设说明角色性格、判断偏好、负责范围和交接边界；Skill 则给出输入、实际工作方法、交付物和验收依据。每个核心专家有独立的人设与一份聚焦 Skill，避免同一个大 Skill 无差别挂给多个角色。姓名均为虚构角色名，不作真人或资历承诺。

## 安装与保留

预览整理清单：`bun run scripts/curate-experts.ts`。应用到当前库：`bun run scripts/curate-experts.ts --apply`。可在参数中指定其他数据目录。

预览会生成/核验模板的内容寻址快照，但不改变启用名单。应用前备份专家 JSON 到数据目录的 `expert-library-backups/`；原人设、Skill 和历史任务快照保留。仅停用识别出的 WorkBuddy 批量导入专家，不停用用户另建专家。新专家使用稳定的 `core-*` ID。核心名单一次写入；冲突或模板缺失不会部分停用旧名单。重复整理保留同 ID 的用户修改和启停选择，不静默覆盖。

界面默认列出启用专家，停用名单和核心模板折叠展示；每条显示 Skill 数量或待补齐状态。新数据目录仍由用户选择模板添加，不在打开设置时自动改变名单。已派发实例保持旧版本，后续任务才使用新版本。旧格式及无 Skill 的历史专家仍可读取，本轮不对用户自定义库施加破坏性迁移。

核心包只有方法文本，不代表自动获得模型、GPU、数据库、生成服务或外部平台权限。服务未启动/不可访问时上报缺口；视觉创作先查看真实参考。研究/创作方法可通过专家 Skill 使用，实际工具和执行范围继续由当前任务决定。

## 验证方法

- `skill-creator/scripts/quick_validate.py` 检查全部 13 个 Skill 的结构。
- `bun test ./test/agent-presets.test.ts` 覆盖 13 类检索、独立实例 Skill 快照/读取、迁移、冲突、编辑保留和旧快照复用，以及现有 API/派发行为。
- `bun run scripts/probe-core-experts.ts` 使用 MiMo V2.6 Flash，在只提供 Skill 读取工具的隔离目录中抽查后端授权、科研伪重复/测试集泄漏、生成服务不可用三个场景。脚本记录提示、专家哈希、工具调用和原始回答；自动检查加载与运行完成，内容质量需要另行审阅。
- `bun run check`、`bun test ./test` 和 `bun run build:desktop-ui` 验证类型、项目回归与 UI 构建。整体测试范围明确排除 `reference/oh-my-pi` 上游测试。

格式正确与场景抽查不构成 13 个专家全领域表现保证，也不等于真实数据库、GPU 实验或视频生成已经验收。后续按真实任务结果进行局部修订。

参考仓库、精确版本和未采用内容见 [来源记录](../presets/agents/SOURCES.md)。

- 当前工作树类型检查通过；全项目回归为 **225 pass / 0 fail / 1215 assertions**（44 个测试文件）。末轮人设/方法调整后，专家相关 8 项测试、144 个断言再次通过；13 份 Skill 结构验证通过。
- UI 构建通过，保留现有大 chunk 提示；隔离服务器 API 实测返回 13 个启用、1 个停用样本，启用项全部有 Skill。内置浏览器访问本地测试地址遇到 `net::ERR_BLOCKED_BY_CLIENT`，未完成界面人工操作/视觉验收，未改用外部浏览器绕过。
- 当前项目库已应用整理：13 个启用核心专家、94 个停用旧专家，共 107 条。94 份旧定义逐项比较未变；备份为 `.alpha/expert-library-backups/agent-presets-2026-09-27T06-02-24-998Z.json`，迁移报告为 `.alpha/core-experts-curation-report.json`。
- MiMo 抽查有失败并全部保留：首轮探针工具注册不完整，修复为与运行时一致的显式工具名单后重试；第二轮后端发现越权但对未约定状态码/数据恢复说得过满，科研分析发现伪重复和测试集泄漏，但长输出超时。已据此补充方法边界和按请求控制交付范围。
- 最后一轮每场景 90 秒、最多 6 次工具调用，追加 500 字以内/不额外生成代码的提示。视觉场景完成并读取 Skill；后端读取 Skill 后超时，统计场景在读取前超时，因此本轮行为抽查仅 **1/3 完整完成**，不宣称三场景或全部专家能力验收通过。原始记录位于 `.alpha/probes/core-experts-2026-09-27T06-00-55-558Z/report.json`；前两轮分别为 `05-54-40-902Z` 和 `05-57-26-329Z` 同前缀目录。
