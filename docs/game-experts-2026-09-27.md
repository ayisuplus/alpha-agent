# 平面（2D）游戏开发专家扩展

日期：2026-09-27。本轮在不改动现有 25 个核心专家人设与 Skill 的前提下，为平面游戏开发新增 4 位专家，每人一份独立人设和一份聚焦 Skill。项目协作规范见根目录 [AGENTS.md](../AGENTS.md)，来源与口径见 [SOURCES.md](../presets/agents/SOURCES.md)。

## 设计原则

- 与现有工程线划清边界：前端、后端、架构师、UI 设计师、测试专家面向通用软件工单；游戏线只处理 2D 游戏特有的循环、手感、资产与平衡问题，不复制一套通用 Web 工程 Skill。
- 与内容线划清边界：视觉导演负责宣发与成片素材，故事专家负责剧情与角色对白；游戏美术只做游戏内可运行资产与动画帧表，游戏设计只做玩法与数值。
- 不绑定引擎：2D 程序 Skill 写通用工程原则（固定步长主循环、状态机、碰撞与手感、图集批处理、帧预算），到具体工单再按用户项目选定 Phaser / PixiJS / Godot / Cocos Creator 等，并在动手前与用户确认，不擅自引入依赖。
- 可测优先：手感、平衡、性能都不用形容词下结论——设计阶段就把"好玩"换成可观测信号（通关率、时长分布、失败点分布、机制使用率、帧时间分布），由试玩专家实测。
- 数字不预支：图集上限、帧预算、输入延迟、加载耗时一律要求实测或查所用引擎官方文档并注明版本与日期，本文档与人设不提供固定数值。

## 工作流与交接

```
玩法与系统（关弈：核心循环、数值表、反馈契约、验证清单）
   → 引擎实现（邵帧，引擎未定时先与用户确认选型）
   → 资产与动画（秦格：规范 → 清单 → 图集/帧表，与邵帧对齐挂点与事件帧）
   → 试玩与平衡（何准：信号表 + 缺陷清单 + 平衡建议）
   → 回到关弈确认数值调整 → 邵帧修复 → 何准复测
```

剧情向作品在此链路上叠加快故事专家（世界观、角色与对白），游戏内界面流程与可访问性对接产品交互设计师，宣发素材对接视觉导演。交接按任务需要发生，不强制每个环节都走一遍；调度与最终验收仍由主代理负责。

## 验证方法

- Skill 结构校验：`python skill-creator/scripts/quick_validate.py`，4 份新增 Skill 全部通过。
- 专家测试：`bun test ./test/agent-presets.test.ts`，覆盖 29 类专家的检索匹配、Skill 快照读取、数量断言与迁移行为（本轮已同步更新检索词与数量断言）。
- 回归与类型：`bun run check`。

结构校验与单元测试只证明格式正确、可被检索与派发，不代表任何具体游戏的可玩性、平衡性或性能表现；真实结论只能来自目标平台上的试玩与实测。后续按真实工单结果局部修订。
