# 动态专家协作

Alpha 使用 TaskLedger 保存任务目标、验收证据、认知修订、实际调用的实例与 Skill 提案。任务开始时有初始认知；模型可通过 `alpha_plan` 修订候选专家和步骤。候选名单只用于计划，`alpha_spawn` 派发具体工单时才在独立 Git worktree 中创建实例。子实例可使用当前任务已授权的工具并修改 worktree 内的项目文件；主实例检查实际差异后逐个决定是否集成。没有匹配专家时，工单以通用执行上下文运行。

最终源码审查也作为全权限 worktree 子实例运行。审查通过需要引用当前源码原文；如果审查实例修改了代码，主实例先检查差异并决定是否集成，随后才将审查结论绑定到当前源码版本。

Alpha 管理的生成/复制工作区在首次派发时会建立本地空 Git 锚点。直接打开的项目必须本身是已有提交的 Git 仓库根目录；否则派发会明确提示，最终审查等待该条件满足，不会改动用户目录的 Git 状态。

专家库只保存用户添加的专家。旧的前端、后端、设计和测试预设作为可选模板展示，不会自动加入。新建或编辑的专家保存为版本化专家包：`PERSONA.md` 记录人设与专业方法，`skills/` 保存选择的已安装 Skill 的完整只读快照，清单记录内容哈希。用户可在新任务中明确指定专家；该选择必须保留在计划中，而且要有实际完成的专家实例才算满足。旧版 JSON 专家仍可读取，修改后生成专家包。

专家包位于任务数据目录的 `expert-packs/`，不会安装到全局或内置 Skill 目录。认知虚拟机只读取专家元数据进行候选选择；派发具体专家时，才为该实例加载随包 Skill，并按工单筛选所需项。停用或删除原插件不会改变已打包版本。执行模式和工具权限仍由运行时决定；专家文本和随包 Skill 都不能增加权限。计划修订读取当前已启用的专家和可用 Skill；已经派发或完成的步骤不能被修订改写。已经派发的工单保留专家、源码和 Skill 快照；专家库后续修改不改写历史实例。

开发任务通过 `runDevelopmentWorkflow` 调度。主实例完成实现后，独立只读会话检查实际源码和任务要求，提交 `pass`、`changes-requested` 或 `inconclusive`。最多自动修复两轮；任务完成仍需要同一契约和源码版本的实际验收证据。调查和审查工单不取得写权限。

Worker 是带独立上下文的执行实例，不是专家类型。主协调实例负责计划与验收；具体工单可以使用调查、实现或审查模式，并选择一个专家包或保持通用执行。最终独立审查也是单独实例。CLI 的 `run-code`、恢复执行和服务器代码任务共用代码验收门禁。

本地 WorkBuddy experts 可用 `bun run scripts/import-workbuddy-experts.ts <marketplace-dir> <data-root>` 导入。导入器只把各插件顶层 `agents/*.md` 作为专家；位于 Skill 内的 `agents/` 文件保留为随包资源。插件清单声明的 Skill 复制进该专家的版本包，不启用原插件的 Hook、MCP，也不进入全局 Skill 目录。重复导入保留用户后续编辑过的同 ID 专家。初始提示只给出少量候选，需要其他专业时用 `alpha_expert_search` 查询元数据。

所有实例都有 `alpha_browser`。协调实例和最终审查使用当前任务的本地预览；隔离 Worker 的浏览器调用通过独立请求记录转发至主侧同一适配器，并串行执行，导航仍受预览来源限制。没有连接预览时明确返回不可用，不能凭模型描述完成视觉验收。Worker 可在工单范围内读写、构建、运行已配置的低风险检查并读取随包 Skill；联网、MCP、媒体、不受控命令及新增专家或派发需要 `alpha_capability_request` 留下请求，由主侧处理后重新派发。只读审查可读取项目内非敏感源码，但不能写入或读取已知凭据路径。

`alpha_gap` 记录方法、工具、权限或上下文缺口。方法缺口可以使用通用公开技术词查询 skills.sh；结果只作为提案。提案包含 GitHub 仓库、精确提交、`SKILL.md` 路径及其声明的工具、服务和冲突要求。用户批准后，仅复制该提交中的目标 Skill 目录及其资源，并保存内容哈希以检查后续重用。搜索接口属于外部实验性依赖：服务不可用或结果无法精确定位时显示原因，不切换到其他在线来源。

Skill 可以在 frontmatter 中声明 `requires-tools`、`requires-services` 和 `conflicts-with`。派发前检查这些显式要求；工具执行时再次按模式检查权限。运行时不会把 Skill 中的文字当作授权。
