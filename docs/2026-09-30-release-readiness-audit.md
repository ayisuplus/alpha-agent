## 侧边栏与操作入口的缺口

目前左栏实际只有：新会话、在其他目录开始、会话列表、设置；有旧记录时加折叠的旧版任务。`NativeSidebar.tsx` 没有搜索、会话状态或操作菜单。

| 类别 | 当前事实 | 最小补齐范围 |
|---|---|---|
| 已有功能的导航 | 技能、定时任务、本机能力都已有页面，藏在设置分组内；每次打开设置默认停在模型页。 | 增加三处直接入口，复用现有页面；模型与账号可保留在设置中。 |
| 会话查找 | 会话线性罗列，标题与目录可见；没有搜索、置顶、项目分组。 | 先补标题/目录搜索与清晰的当前会话标识。分组、置顶可作为后续增强。 |
| 会话管理 | 没有改名、归档、恢复、导出或原生分支操作入口；会话 API 也没有归档元数据。OMP RPC 已有 `set_session_name`、`export_html`、`get_tree`、`branch` 等能力。 | 会话菜单先补改名、归档/恢复、导出；原生分支入口按使用需求补。不要把“新会话”当作“复制分支”。 |
| 运行与注意事项 | 左栏不能看哪些会话正在工作、等待输入、已失败或已经结束；没有跨会话注意事项列表。 | 显示最小运行状态及等待输入/失败标记，能跳到需处理的会话。 |
| 原生工具与扩展 | “运行与工具”可以改部分原生设置；没有 MCP 服务列表/连接状态、插件管理、完整 Skill 来源清单和 OAuth 登录入口。技能页只列 30 个随包方法，真实 OMP `get_available_commands` 还能发现用户自有 Skill。 | 先提供原生命令入口与状态说明，再按必要性做可视化管理；不能把已有内核能力在桌面里显示成不存在。 |

上述导航结构是功能接线建议，没有重做视觉样式，也不恢复已取消的专家、计划图或旧任务编排系统。

## 开源与验收链的遗漏

- README 缺少从干净检出开始的安装步骤、支持系统/架构、Bun/Office/ComfyUI 前置条件与首次模型配置说明；目前主要给的是开发命令。
- 没有 `.github/` CI、SECURITY.md 和贡献入口。可先补 Windows 的 check/test/skills/build 自动检查与问题反馈模板，无需一次构建复杂发布平台。
- `eval/README.md` 仍推荐 `bun run eval`，但当前没有该 script；`eval/run.ts:227` 还调用已退役的 `/api/tasks/general`。应明确标记旧架构评测材料，避免让开源使用者以为这是当前验收命令。
- Git 仍跟踪 `.workbuddy/memory/2026-09-27.md` 这类个人协作记录；来源文档还引用已删除的 `presets/agents/upstream/`。公开前需要决定哪些历史记录适合保留，核对引用与归属；本轮没有删除文件或改写历史。
- 当前打包探针能验证包内 UI/OMP/Office，但没有记录构建 Git SHA，也不校验 payload 与当前源码一致；`probe-portable.ts` 没有隔离 OMP 用户配置，验收依赖本机已有账号环境。
- 安装器未签名是已记载的发行限制。完整新安装/升级流程、本机浏览器接管/交还、真实模型任务和真实媒体生成本轮未重测；不应从本地套件通过推断这些都已通过。

## 最小收尾顺序与完成判据

1. 先处理进程回收、定时持久化/完成回执、凭据可用性、浏览器授权及异步错误反馈：20 次并发修改全保留；活动会话不被第 5 次打开杀掉；调度下一次不与上次重叠；目录可用模型能启动；等价浏览器调用都按授权处理；失败在用户可见处明确出现。
2. 补侧栏直达入口、会话搜索和管理菜单，复用 OMP 原生 API；验证改名/归档恢复/导出重启后仍成立。
3. 定许可、补干净安装说明和 CI，处理已退役的评测入口，完成当前树与 Git 历史的公开内容检查。
4. 从修复后的同一 Git 提交重新构建有新版本标识的安装包，记录 Git SHA、校验值与验证结果，跑便携/Office/安装包探针及干净首次启动；再决定正式发行。

这些是审查后的建议施工范围，本轮没有发布、重新打包或修改账号/用户任务数据。进入任务时已有的 `reference/oh-my-pi` 脏状态与 `.tmp-host-window.png` 均保持原样。
