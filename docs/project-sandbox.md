# 项目文件夹与沙箱

新项目可挂载多个本机 Windows 文件夹。任务选择其中一个工作目录和 `ask`、`auto` 或 `full` 权限档位后，直接在挂载目录修改文件。挂载版本写入任务账本；挂载变化、路径身份变化或沙箱探针失败时，任务在模型调用前暂停。旧导入任务仍使用受管理副本和应用审阅流程。

`ask` 与 `auto` 的文件工具及命令使用便携包内固定版本的 Codex Windows 执行器。OMP 模型会话与凭据留在宿主；四个文件工具在 OMP 注册表中被 Alpha 代理覆盖，文件操作在独立子进程中执行。配置为 `elevated`，挂载目录可写，默认网络关闭，已知凭据位置和 `.env` 文件拒读。启动前用真实子进程检查低权限身份、挂载内写入、挂载外写入、子进程越界写入与本机网络拒绝；检查不通过时不运行模型，也不切换到 `unelevated` 或普通进程。首次初始化需要 Windows 管理员批准。

`ask` 的越界文件动作和命令请求由用户逐项批准。`auto` 在相同沙箱边界内把普通命令交给一个没有执行工具的独立审查会话；高危、联网、越界和不确定动作仍交给用户。审批记录包含完整参数、目标、理由、风险、审查者、决定和结果。批准一次只执行一次；重启时运行中的动作标为结果不确定，不能自动重放。批准的越界文件写入或凭据读取由固定文件代理在宿主按原参数单次执行，这次升级不具有 OS 沙箱边界；因此审批界面会展示完整目标与内容。命令联网需单独批准，并使用联网的 Windows 沙箱配置。

`full` 允许当前用户权限的文件和命令访问，普通命令可直接执行。已识别的删除、凭据访问、系统目录写入等高危动作仍需用户批准。这一档没有 OS 隔离；任意脚本内部的危险行为不能保证在执行前被识别。

当前直接项目任务暂不提供第三方 MCP、插件进程、委派 worker 或浏览器工具，避免这些宿主路径绕过执行代理。需要这些工具的任务应使用旧工作区流程；为直接项目开放它们前，必须分别接入同一审批账本和执行边界。便携包的 `scripts/probe-portable-sandbox.ts` 可在移除全局 Codex PATH 后检查包内执行器、服务健康与项目 API；实际拒绝效果仍须在完成管理员初始化的 Windows 机器上通过项目页的“检查沙箱”验证。
