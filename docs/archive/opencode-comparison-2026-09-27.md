# Alpha 与 OpenCode：可审计任务收尾

> 归档（2026-09-30）：本文记录已放弃或已被取代的旧架构与方案，不代表当前版本。当前方向见 [原生 OMP 重构](../2026-09-29-omp-native-refactor.md) 与 [定版收束建议](../2026-09-30-final-convergence-recommendations.md)。

对照日期：2026-09-27。停止条件是 Alpha 至少有一项经验证的差异化优势，而非宣称整体功能或体验领先。

## 对照范围

- [OpenCode 官方介绍](https://opencode.ai/docs/)列出终端、桌面和 IDE 入口；[权限文档](https://opencode.ai/docs/permissions/)列出按操作与输入匹配的允许、询问、拒绝规则。Alpha 不以入口或权限项数量声称领先。
- [OpenCode 快照文档](https://opencode.ai/v2/docs/snapshots)将文件快照标为尽力而为，说明它不创建项目 Git 提交，回滚不能撤销 Git、进程或外部资源的副作用，并建议重要工作使用提交或备份。
- Alpha 的受管理任务轮次由宿主准备项目 Git 基线；观察到写工具调用后，结束时提交相对轮次起点新增的允许路径，并将项目状态写入独立的 Git 历史。已有脏文件保留；若其内容或索引变化，收尾拒绝提交。中断恢复仅承认已存在的本轮提交。

## 本轮修复

以前中断恢复找到本轮代码提交后，可能直接跳过项目工作树检查，尽管提交之后又出现了未提交改动。现在恢复必须确认：项目 HEAD 仍是本轮提交；准备轮次时已有的脏文件内容与索引未变；没有新增的未提交代码改动。任一条件不满足时，恢复拒绝记录完成的检查点，保留文件供人工审阅。

`test/project-state.test.ts` 用真实临时 Git 仓库覆盖了提交写入日志前后、新的未提交改动、后续提交改变 HEAD、用户原有脏文件变化以及正常恢复。验证结果：项目状态 22 个测试通过，完整回归 199 个测试通过，`bun run check` 通过。

## 结论边界

Alpha 在**受管理任务的 Git 检查点和中断恢复**上形成可核查的优势：成功收尾有项目提交及独立状态提交，恢复遇到无法归属的变化会拒绝完成。这是与 OpenCode 文档所述尽力而为快照不同的交付保证；它不证明 Alpha 在模型效果、速度、平台覆盖、插件生态或桌面体验上整体优于 OpenCode。

Alpha 当前仍在可信 Windows 本机执行构建进程，Git 工作树不是操作系统沙箱。上述测试验证的是本地 Git 与任务状态路径，未覆盖真实断电、断网或不可信代码的原生隔离。

活动写入轮次中，外部进程若同时修改一个原本干净且允许提交的路径，当前仅凭 Git 状态无法识别改动归属；这类并发写入尚无独立归属证明。
