# 动态专家开发流程：六次固定小任务验证

> 归档（2026-09-30）：本文记录已放弃或已被取代的旧架构与方案，不代表当前版本。当前方向见 [原生 OMP 重构](../2026-09-29-omp-native-refactor.md) 与 [定版收束建议](../2026-09-30-final-convergence-recommendations.md)。

同一模型 `alibaba-token-plan/qwen3.6-flash` 分别运行 `runTask` 单会话流程和 `runDevelopmentWorkflow` 审查流程。三个任务均从相同初始源码与未修改的测试文件开始：边界钳制、查询参数解析、单复数标签。每次最多 8 分钟、80 次工具调用；没有自动重跑。每次结束后独立执行 `bun test app.test.ts`，核对测试文件 SHA-256。原始账本、源码和结果保存在 `.alpha/workflow-evaluation/2026-09-25/<case>-<mode>/`。

| 任务 | 流程 | 外部测试 | 审查结论 | 工具调用 | 用时 | 记录的总 token |
|---|---|---:|---|---:|---:|---:|
| clamp | 单会话 | 通过 | 无 | 24 | 35.3 秒 | 217099 |
| clamp | 审查流程 | 通过 | 需修改 | 26 | 57.3 秒 | 163912 |
| query | 单会话 | 失败 | 无 | 18 | 28.4 秒 | 153309 |
| query | 审查流程 | 通过 | 通过 | 21 | 29.5 秒 | 146699 |
| label | 单会话 | 通过 | 无 | 19 | 22.6 秒 | 160195 |
| label | 审查流程 | 通过 | 通过 | 23 | 34.4 秒 | 145259 |

`query` 单会话版使用 `split('=', 2)`，把 `token=a=b` 错解析为 `token=a`。审查流程版实现正确；其审查没有触发修复，因此不能把差异单独归因于审查。

首个 `clamp` 审查发生在正式测试证据入账前，模型把“测试尚未验证”误记为“代码需修改”。源码与外部测试实际通过。发现后将审查提示收窄为源码与需求复核，测试通过仍由后续验收门禁判定；保留该原始失败记录，未重跑。后两次审查流程采用修正后的提示，因此这不是严格同配置 A/B 实验。

这六次仅证明当前实现能在真实模型上运行，并暴露了审查和成本上的具体问题。总 token 是 OMP 记录值，可能包含缓存/重复上下文；供应商费用字段为 0，不能解释为零费用。样本过小，不能宣称新流程普遍更准确或更省成本。
