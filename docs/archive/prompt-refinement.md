# 提示词优化与英译：首版规则

> 归档（2026-09-30）：本文记录已放弃或已被取代的旧架构与方案，不代表当前版本。当前方向见 [原生 OMP 重构](../2026-09-29-omp-native-refactor.md) 与 [定版收束建议](../2026-09-30-final-convergence-recommendations.md)。

按钮处理输入框中的任意非空文本，自动归入软件开发、事实与研究、创意生成、写作沟通、通用五类。分类只改变整理方式，不代表目标模型一定会表现更好。不同模型和任务的提示效果需要用实际输出评价，不能仅凭改写后的文字判定。

| 类别 | 允许的整理 | 不允许的补充 |
| --- | --- | --- |
| 软件开发 | 明确现有目标、功能、硬约束、验收条件 | 自选技术栈、功能、测试或上线要求 |
| 事实与研究 | 理顺问题和已给范围，保留证据要求 | 编造事实、来源或新增比较维度 |
| 创意生成 | 整理主体、动作、风格、构图及排除项 | 自行添加人物、画面细节或审美方向 |
| 写作沟通 | 理顺受众、语气、形式和已有观点 | 添加新主张或改变说话者语气 |
| 通用 | 仅改进表述和结构 | 推测任务目标或填补关键缺失信息 |

流程为：输入框对应的任务模型生成分类和同语种优化稿；程序检查原文中的数字、网址、路径和代码片段是否保留；用户指定的英译模型再独立比较原文与优化稿并翻译。核对失败时，改为英译原文并显示原因。界面同时展示原文、优化稿、英文及未明确之处，只有用户点击“使用”才替换输入。

依据与边界：

- [Anthropic 提示词实践](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/prompt-templates-and-variables)建议明确表达目标、格式和约束，但示例和结构应按任务使用。
- [Anthropic 成功标准](https://docs.anthropic.com/en/docs/test-and-evaluate/define-success)要求先定义可观察的成功标准；“更长、更像模板”不是优化效果的证据。
- [用户提示词改写研究](https://arxiv.org/abs/2503.16789)发现改写可能改善回答，也指出模型会对欠明确意图作出推测；因此本功能保留未明确项并由用户复核。
- [自动提示词优化研究](https://arxiv.org/abs/2305.03495)使用任务数据和模型结果挑选候选；本功能没有这类任务数据，所以只称“整理并英译”，不声称自动提升下游质量。

程序校验和第二次模型核对都不能证明语义完全等价。最终采用权在用户；真实效果应按具体任务、目标模型和输出结果评估。
