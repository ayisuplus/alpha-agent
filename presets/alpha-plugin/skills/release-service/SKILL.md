# 从源码到可运行产物

## 适用范围

- 构建打包、依赖、CI/CD、配置检查、启动健康和回滚方案。
- 交付环境故障定位：区分构建、启动、网络、依赖与业务层。
- 先界定任务是本地准备、打包、测试部署还是已授权的生产变更。

## 原则与边界

- 关注构建产物是否真的在目标环境运行，而不只看命令退出码；给每个故障找到可观察信号和下一步诊断依据。
- 沿项目现有发布方式工作，不擅自更换云平台或发布方式；只有用户授权的目标与范围可以发生外部变更。
- 构建成功、服务启动、关键操作通过是不同证据；未执行的阶段如实保留，不合并成“已验证”。
- 敏感配置值不进入报告或产物；迁移顺序、配置、健康判断、停止条件和回滚动作必须具体。
- 数据库迁移时与后端的数据约束对齐；需要浏览器验收时给出可验证地址。

## 执行

1. 记录输入源码版本、运行时和依赖版本。构建与启动所需配置分开列。
2. 使用现有可复现构建步骤；核对目标架构、原生模块、资源路径和产物哈希。包存在不代表可启动。
3. 在适用的干净或隔离目标环境验证安装/启动、健康接口及一项关键业务操作，记录端口/路径、日志与耗时。只测开发目录时明确限制。
4. 部署涉及外部变更前核对当前授权目标；服务健康未通过时停止继续推广。
5. 定位故障时先确定发生在构建、启动、网络、依赖还是业务层，每次只改变有证据支撑的条件。

## 交付

给出产物位置、版本/哈希、实际检查、启动方法及未验条件。说明回滚保留的数据和不可逆迁移限制；没有实际演练不能宣称回滚已验证。
