# 从受众问题到内容

## 适用范围

- 受众定位、选题、文案结构、品牌语气和平台改编；产出选题方案、长短文案、标题/封面文案与发布说明。
- 科学内容中的主张以研究证据为准，商业数据和案例不能靠创意补齐。

## 原则与边界

- 用一个具体的观察支撑选题，拒绝千篇一律的口号和没有依据的流量承诺。
- 先阅读用户既有内容与真实参考，辨明哪些是风格、哪些是事实；记录来源及借鉴的结构或表达方法。
- 重要事实、案例与数字可追到来源；区分虚构故事、个人观点和事实陈述。
- 纯局部文字修改按原文完成，不扩大成营销策划。
- 内容审核不等于已发布；发布、账号操作和投放需符合当前授权；传播效果用发布后的真实数据评估，不预先承诺流量、转化率或收益。

## 创作方法

1. 确定受众、用途、平台、格式和用户想保留的语气；用一个明确的读者问题组织内容，选择有证据支撑的角度。
2. 按目标形式安排开头、信息展开和结尾动作。少用空泛口号、连续形容词与模板化反转，用具体细节表达观点。
3. 平台改编保留原信息主干与事实，调整篇幅、标题、段落和观看场景；平台限制或趋势有时效性时查官方/真实页面，不能靠记忆宣称当前规则。
4. 为需要的视觉给出明确简报：传达什么、必须保留什么、素材来自哪里。需要剧情与镜头素材时，可按 `write-story` 与 `direct-visuals` 的方法另行制作，避免一次重写所有阶段。

## 工具用法

- 读取素材：用 OMP 原生 `read` 工具按路径直接读 docx/xlsx/pptx/pdf/epub，转为 Markdown 后理解内容；网页调研用 `web_search`/`fetch` 核对来源与平台规则。
- 交付成稿：正文与发布说明用 Markdown 交付；需要 docx/pdf 成品时用 `alpha_office create`（Markdown→docx/pdf）写入项目内 `outputs/`，需要改已有文档时用 `edit`（按地址编辑，永不覆盖原件，输出 `<原名>.alpha-v<N>.<扩展名>`），每次 `create`/`edit` 后用 `preview` 自检。工具返回 `{ summary, artifacts: [{ path, kind, sha256, preview? }] }`。
- 配图需求用 `alpha_generate_image` 出概念图，产出写到 `outputs/media/<可读名>.<扩展名>`；ComfyUI 服务不可用时上报缺口，不代替用户启动服务。浏览器自动化用 `eval` 的 `browser` 命名空间（browser.open/run/call/tabs…，需用户授权）。
- 超出能力范围时如实上报缺口，不虚构素材与效果数据。

## 交付

按用户所需输出正文、标题/封面文案及发布说明，避免无意义地列几十个候选。标记事实待核验、素材待授权和未制作项。
