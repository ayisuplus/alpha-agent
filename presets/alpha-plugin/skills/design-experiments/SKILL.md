# 有边界的实验设计

## 适用范围

- AI/计算机实验为主：训练与微调、推理与提示、基准评测、智能体与系统性能；其他学科按实际研究单位、随机化与对照设计调整。
- 观察、假设、竞争解释与能区分它们的预测；主要指标、最小有意义差异与成败判据。
- 实验单位、数据划分与泄漏检查；基线（简单基线、强基线、最接近的已发表方法，区分复现值与抄录值）、消融与合理性检查。
- 种子数与重复设计；调参、算力与推理预算的公平对齐；资源估算、冒烟测试、停止与转向规则；复现包（提交号、环境、配置、数据版本、命令、日志）。

## 原则与边界

- 把宏大主张拆成可被否定的问题，先问"什么结果会让我们放弃这个说法"；对"只差再跑一组"的无边界试验保持警惕。
- 眼亮数字背后常见调参预算不对等、数据泄漏、测试集反复使用或只报最好的种子，在运行之前就把这些路堵上。
- "代码能运行""原文结果能复现""新方法得到支持"三个层次分开回答，前一层成立不等于后一层成功。
- 运行前冻结假设、主要指标和分析计划，之后新增的分析一律标为探索性；失败、重启、负结果和预算消耗全部保留，不覆盖原记录。
- 框架、模型 API、硬件与基准的行为和版本会变化，涉及具体版本、价格、配额与限制时查官方文档或实测并注明日期。
- 所需算力、数据、模型访问不可用时先上报缺口，交付受限方案，不能宣称实验已完成或写出未运行的数字。
- 正式运行、调用付费 API、下载大型数据集或模型之前需要用户授权。

## 输入与前置阅读

1. 读用户目标、论文与代码、已有实验日志和结果、可用算力与数据。先确认要回答的是哪一层：
   - 可运行：代码和流程能跑通；
   - 复现：用原作者的代码、数据和配置得到与原文一致的结果（在原文报告的波动范围内）；自己重写实现得到一致结果则是独立复现；
   - 支持：拟议方法在预先确定的比较下优于合理基线，并说明在哪些设置下成立。
2. 确认资源上限：GPU 型号与时长、API 费用、墙钟时间、存储；确认数据与模型的许可和访问权限。
3. 涉及大模型、基准评测、智能体任务或以模型为评判者时，读取 `references/ai-evaluation-checklist.md`。

## 工作步骤

### 1. 问题与预测

- 写出观察、待检验假设、至少一个竞争解释，以及能区分它们的预测，例如"如果提升来自组件 X，去掉 X 后指标应回落；如果来自更多的调参，给基线同等调参后差距应消失"。
- 冻结主要指标及方向、主要比较（谁与谁比）、最小有意义差异（小于它即使统计显著也不算改进）和成败判据。其余分析一律标为探索性。

### 2. 单位、划分与泄漏

- 明确实验单位（样本、用户、会话、代码仓库、文档、种子）及其独立性；同一对象的多个样本放在同一个划分里（按组划分），有时间顺序的数据按时间划分。
- 固定训练、验证、测试的用途：预处理拟合、特征选择、调参、早停和选模型只用训练与验证数据。测试集参与过任何选择后必须披露，不能再称为无偏的最终测试。
- 泄漏检查：训练与测试间的重复和近重复、同源样本、时间穿越、标签信息混入特征、预训练语料包含测试数据。能检查的实际检查并记录方法，不能检查的写入局限。

### 3. 基线、消融与合理性检查

- 基线分三类：简单基线（多数类、随机、线性探针、只用提示等）、公认的强基线、最接近的已发表方法。标明每个数字是自己复现还是从原文抄录；抄录值只在条件一致时并列。
- 公平对齐：数据、预处理、调参预算（试验次数与搜索空间）、训练步数、算力与推理预算（采样次数、上下文长度、工具调用）、评测脚本。对不齐的地方在结论中限定。
- 每个消融对应一个要排除的解释，不为表格完整而穷举组合。加入合理性检查：打乱标签或输入、去掉关键信息的对照、上界或下界设置，确认评测流程能区分好坏。

### 4. 重复、种子与规模

- 先用小规模试点估计种子间的波动，再决定正式运行的种子数；差异接近噪声时增加种子或扩大测试集。种子在运行前固定并全部报告，不事后挑选。
- 分清波动来源：训练随机性（初始化、数据顺序、dropout）、测试集抽样、调参选择、硬件与库的非确定性。重要结论至少覆盖训练随机性和测试集抽样两类。
- 有多个数据集或任务时，事先决定逐项报告和汇总方式，避免只挑有利的数据集。

### 5. 预算、执行与停止

- 运行前给出资源表：配置数 × 种子数 × 单次时长 = 总 GPU 小时或 API 调用量与费用，另留失败重跑的余量。
- 先跑冒烟测试（极小数据、几步训练、端到端评测）检查数据、指标和日志，再做已授权的正式运行。
- 写明停止与转向规则：达到预算上限、试点显示效应远小于最小有意义差异、发现泄漏或评测错误时，停止相应运行并报告，不默默延长或扩大搜索。
- 每次运行登记：运行 ID、提交号、配置哈希、种子、开始与结束时间、状态（成功、失败、中断、重跑）、资源消耗、结果路径。失败原因照实记录，不覆盖旧结果。

### 6. 复现包

- 固定代码提交、依赖锁文件或容器、数据版本与校验和、配置文件、随机种子、完整命令行、硬件信息和预计耗时。
- 训练与评测分开入口，评测可以从保存的模型或预测结果单独重跑。
- 数据与模型的许可、隐私和使用限制写进说明；涉及人类受试者、个人数据或潜在滥用时，提示用户确认伦理审批与合规要求。

## 交付物

- 实验方案：假设与预测、主要指标与判据、实验矩阵（设置 × 基线与消融 × 数据集 × 种子）、划分与泄漏检查、公平对齐表、资源表、停止规则。
- 分析计划：写清统计单位、配对关系、预先确定的主要比较与汇总方式，供后续结果分析按同一口径执行。
- 执行时：运行登记表、失败与负结果记录、复现包与说明文档、结果文件位置。
- 分层结论：可运行 / 复现（与原文的差异及可能原因）/ 支持程度（在哪些设置下成立，哪些尚未测试）。

## 验收依据

- 主要比较与判据在运行前冻结且有记录；每个结果能追到运行登记和配置；基线来源标明；失败与负结果保留；资源消耗有实际记录。
- 缺少算力、数据、模型访问或授权时，交付受限方案（缩小规模、改用可获得的基准、只做评测不做训练），写明它能回答和不能回答的问题。
- 文献依据在方案中标注出处；数据许可、隐私与伦理审批由用户确认后再执行正式运行。
