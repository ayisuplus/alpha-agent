# 文档格式处理全链路

## 适用范围

- PDF 创建、合并、拆分、页面操作（旋转、按页提取）、水印添加，以及 PDF↔Word↔PPT↔表格↔文本之间的格式转换。
- Office 文件的内容解析提取；场景包括合同合并归档、扫描件整理、报告导出为 PDF、多格式互转等。
- 先检查源文档的复杂程度（表格、图片、多栏、扫描件），再选处理路径。

## 原则与边界

- 关注格式保真与转换损失：不在格式丢失时假装没看见，不承诺零差错转换。
- 复杂排版（表格/多栏）转换后标注需人工复核区域；重要合同和公文转换后建议人工逐页复核。
- 页数、页序和关键内容以原文件为准；处理前记录原件路径，永不覆盖原件。
- 超出能力范围的功能不虚构结果：如实上报缺口，并给出可行的替代路径或请用户补材料。

## 工作步骤

1. 确认源文档格式、目标格式和核心需求（归档/编辑/分发/提取），用 `read` 读取内容评估复杂度。
2. PDF 创建：从 Markdown/文档生成 PDF，检查页边距、字体嵌入和图片分辨率。
3. 合并与拆分：按页码范围拆分；合并时检查页面方向一致性、页码连续。
4. 水印：支持文字水印和图片水印，说明位置、透明度、是否覆盖所有页面。
5. 格式转换：PDF→Word、PPT↔PDF、Word↔PPT 等转换说明可能的排版差异；转换后逐项核对页数与关键内容。
6. 文档解析提取：从 Office 文件提取文本、表格、图片等结构化内容，保留章节结构。
7. 扫描件处理：先评估清晰度；模糊、倾斜、遮挡区域标记无法识别。

## 工具用法

- 读取文档：用 OMP 原生 `read` 工具按路径直接读 docx/xlsx/pptx/pdf/epub，转为 Markdown 后理解内容。
- 办公生产与编辑用单一工具 `alpha_office`，按路径进、按路径出，永不覆盖原件：
  - `inspect`：列出段落、表格、工作表、页面等可编辑地址；
  - `edit`：按地址编辑，输出 `<原名>.alpha-v<N>.<扩展名>`，带前后预览；
  - `create`：Markdown→docx/pdf、表格数据→xlsx，写入项目内 `outputs/`；
  - `convert`：docx/xlsx/pptx/odf/html/pdf 互转，写入 `outputs/`；
  - `pdf`：合并、拆分、旋转、水印、按页提取；
  - `preview`：指定页渲染 PNG 自检。
- 每次 `edit`/`create`/`convert`/`pdf` 后用 `preview` 自检（页数一致、关键内容不丢失、水印与方向正确），再交付；工具返回 `{ summary, artifacts: [{ path, kind, sha256, preview? }] }`，产物都在项目内。
- 限制说明：PDF 表单字段填写、扫描件 OCR 识别、图片格式转换不在 `alpha_office` 当前动作范围内；遇到这类需求如实上报缺口——表单填写建议人工或专用工具完成，扫描件建议先经 OCR 工具转出可选中文本再交来处理。LibreOffice 缺失等环境问题同样如实上报，不虚构结果。

## 交付

默认交付目标格式文件及转换说明，标注已知格式损失类型（表格位移、字体替换、图片丢失、低置信区域）。输出前自检：页数一致、关键内容不丢失。
