# 从交互到可运行前端

## 适用范围

- 组件、状态归属、接口接入与浏览器交互的实现与修复；沿“用户操作 → 页面逻辑 → 状态 → 请求 → 可见结果”定位问题。
- 初始、加载、空结果、成功与失败等界面状态的处理；提交失败的输入保持与错误恢复。
- 浏览器内的实际操作验证、可见结果记录与页面检查。

## 原则与边界

- 优先使用项目已有的组件、样式和技术栈，避免为小改动建立新框架；设计输入不足时采用现有模式。
- 确需新视觉方向时先取得真实参考或已批准设计，不编造设计依据。
- 后端未实现的行为明确标记，不用演示数据伪装真实功能；接口不明确时提供真实调用位置和所需契约，不虚构 API。
- 代码改动限定在当前任务范围；接口歧义如实说明，由调用方协调。
- 测试报告分别说明自动检查结果和实际看过、操作过的页面；构建通过不能代替浏览器验证。

## 实施

读取相关页面、组件、状态层、接口类型、样式和项目检查命令，把一条用户路径作为实现范围。

1. 确定状态归属和数据权威来源，沿用现有模式。派生值从来源计算，避免额外状态造成不同步。
2. 对接真实接口契约。处理当前任务涉及的初始、加载、空结果、成功和失败状态；提交失败保留可恢复输入。搜索、切换或多次请求应检查旧响应是否覆盖新状态。
3. 使用语义控件、标签和键盘路径；复用样式约定，检查受影响的小屏与长内容。只有性能证据或明确需求才增加 memo、虚拟列表或代码分割。
4. 修复逻辑缺陷时先复现或补能失败的行为测试，再做最小修改。简单可逆样式变动可用页面检查，不写只复述代码结构的测试。

## 工具用法

浏览器自动化用 `eval` 的 `browser` 命名空间（同一可见浏览器，保留登录态；首次使用会询问会话级授权）：

- 打开与读取：`await browser.open({ url })` 打开页面，`browser.tabs()` 列标签；读页面内容优先 `await tab.extract("markdown")`，看结构用 `tab.ariaSnapshot()`。
- 稳定操作：先 `await tab.waitFor(selector)` 等元素出现再操作；点击与填表优先用**元素句柄**——`const el = await tab.waitFor("#go"); await el.click(); await el.fill("文本")`——或用稳定选择器（id、角色、可见文本），不做坐标点击。
- 键盘与滚动：`tab.press(key)`、`tab.type(selector, text)`、`tab.scroll(dx, dy)`；等待跳转后重新 `waitFor` 目标元素。
- 每步操作后读回 DOM 或元素文本核对结果，不以“没报错”当成功；需要留证时 `await tab.screenshot()`。
- 表单提交、发布、后台写操作必须先获得用户明确授权；授权弹窗按“仅这次 / 本会话 / 拒绝”如实选择，不绕过、不代答。

## 验收

按项目已有命令运行适用检查。浏览器可用时实际操作变化路径，记录可见结果及错误信息；核对所测页面来自本轮代码。不能用占位数据、截图或构建成功证明后端持久化成功。

交付变化的用户行为、相关文件、执行命令和结果、未验项。
