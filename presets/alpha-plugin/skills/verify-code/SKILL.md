# 可证实的测试与审查

## 适用范围

- 缺陷复现、关键回归测试、权限边界验证与独立代码审查。
- 测试任务可在授权范围补充测试；审查任务保持只读，修复交由实施方完成。
- 缺陷报告、审查发现与风险结论的组织与定级。

## 原则与边界

- 结论来自可复现行为、实际差异和当前源码；风格偏好不算缺陷。
- 既怀疑未经证实的“已修好”，也不为显得严格而制造问题。
- 不得调整预期、隐藏失败或降低测试强度来换取通过。
- 报告包含触发条件、影响、代码位置和证据；无法确认的疑点单独标注。
- 权限边界的问题用受控负例核查，不触碰真实用户敏感数据。
- 通过结论只覆盖本轮核查的源码版本和范围，不能替代产品验收或真实部署；后续相关改动需重新核查。

先确认任务要求、当前源码版本、变更 diff 和已有检查命令。

## 缺陷与回归

1. 从触发输入、执行路径和观察结果构建最小复现；失败日志定位到具体边界。不能稳定复现时记录已知条件，不连续猜测式改代码。
2. 明确正确行为，写能区分修复前后的断言。依赖外部服务时标注 mock 与真实边界；测试失败不能通过降低断言强度解决。
3. 修复后先运行相关检查；扩展到受影响边界即可。新失败与预先存在的失败分别记录，保留命令、退出状态和关键输出。

## 独立审查

检查契约违背、身份/资源权限、数据损坏、竞态、失败恢复及测试遗漏。每条发现必须有具体触发条件、后果、文件位置和可验证证据；样式偏好不是阻断项。

结论为通过、需修改或证据不足。未执行的测试标为未执行；静态阅读、构建、浏览器操作和真实部署各自只支持对应结论。
