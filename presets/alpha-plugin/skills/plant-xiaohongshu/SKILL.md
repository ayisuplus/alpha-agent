# 小红书种草策划

## 适用范围

- 账号定位与垂类权重、关键词与搜索意图研究、选题与选题库、封面与标题。
- 图文/视频笔记结构、正文与话题标签、评论区运营、合集与专栏规划。
- 品牌种草、探店测评、攻略教程等类型的内容方案。

## 原则与边界

- 把小红书理解为“带社交属性的搜索引擎”：用户带着生活问题和购买决策来搜索，为“有用、可存、可信”的笔记停留，对硬广和堆砌关键词高度敏感；一篇笔记解决一个具体问题。
- 时效核对：平台算法（搜索与推荐的流量占比、CES 评分类公式、点击率与收藏率阈值等）更新频繁且来源口径不一，只作待核实的线索；动手前查小红书创作中心、蒲公英/聚光官方说明和真实搜索结果页，注明核对日期。
- 不堆词、不做伪素人话术、不虚构体验和效果数据；如实标注身份与合作关系，品牌合作与营销信息按平台规则标识。
- 医疗、金融等受限领域先核资质与功效表达边界；素材与肖像需授权。
- 发布、私信和投流需符合当前授权；不承诺爆文、流量与转化结果。

## 一、关键词与选题

按“搜索 + 推荐”双流量组织内容：标题和封面承担点击，首图与首行承担留存，正文自然布局核心词与长尾词；攻略、避坑、清单、真实记录类内容优先争取收藏与关注。

1. 从真实搜索场景找词：在小红书搜索框输入核心词，记录下拉联想、相关搜索、结果页排序与高赞笔记标题；结合季节、场景、人群、痛点扩展长尾词。关键词反映生活方式与购买决策，不照搬通用搜索引擎的选词逻辑。
2. 判断每个词的搜索意图（找攻略 / 做对比 / 看测评 / 求避坑 / 找灵感），选题与意图一一对应；优先做自己有真实体验或信息优势的题。
3. 高收藏题型优先：攻略教程、避坑清单、步骤记录、真实对比、合集盘点；标题和选题要给出明确结果承诺，但不夸大、不虚构体验。
4. 建立选题库，按“核心词 × 场景 × 人群”批量规划，保持垂类稳定更新以积累账号权重。

## 二、封面与标题

1. 封面承担点击：首图用高清画面＋醒目大字，直接写痛点或结果（"看完能得到什么"），主体明确、版式统一；信息流中一眼可辨主题。点击率门槛等数值只作参考，以创作中心当前口径为准。
2. 标题控制在平台当前建议长度（常见 15–25 字），包含 1 个核心关键词，用"问题/人群＋具体结果"结构，可加数字、场景、时间等限定；不用空泛副词，不做与内容不符的标题党。
3. 图文笔记准备 3–6 张高清图：首图痛点/利益点，后续图按步骤、对比、细节、结果组织，必要时加简洁文字标注；视频笔记同样以前 1–3 秒和封面抓人。

## 三、正文与发布

1. 首行承接标题、迅速给价值；正文短段落、分点写清步骤或要点，自然嵌入 3–5 个长尾词（首尾各出现、中间分散），语言像真实用户分享，不生硬堆词——语义识别下关键词堆砌可能被限流。
2. 如实标注身份与合作关系：品牌合作、赠送样品、营销信息按平台规则标识；不写伪素人话术，不虚构使用经历和效果数据。
3. 话题标签选垂直精准词；善用合集、置顶笔记承接系列内容。发布后回复提问型评论并补充信息，评论区本身也是搜索与信任资产。

## 四、复盘

1. 对照曝光、点击（封面/标题）、停留与完读、收藏、评论、关注、搜索进店等数据定位问题；区分流量来自搜索还是推荐，分别优化关键词与封面选题。
2. 以创作中心等官方后台为准，CES 评分类公式与流量阈值为第三方/经验口径，先核实再引用，不向用户保证爆文。
3. 每轮迭代形成关键词与选题假设的验证闭环；跨平台对比与周期统计可按数据复盘方法进行。

## 工具用法

浏览器自动化用 `eval` 的 `browser` 命名空间（同一可见浏览器，保留登录态；首次使用会询问会话级授权）：

- 打开与读取：`await browser.open({ url })` 打开页面，`browser.tabs()` 列标签；读页面内容优先 `await tab.extract("markdown")`，看结构用 `tab.ariaSnapshot()`。
- 稳定操作：先 `await tab.waitFor(selector)` 等元素出现再操作；点击与填表优先用**元素句柄**——`const el = await tab.waitFor("#go"); await el.click(); await el.fill("文本")`——或用稳定选择器（id、角色、可见文本），不做坐标点击。
- 键盘与滚动：`tab.press(key)`、`tab.type(selector, text)`、`tab.scroll(dx, dy)`；等待跳转后重新 `waitFor` 目标元素。
- 每步操作后读回 DOM 或元素文本核对结果，不以“没报错”当成功；需要留证时 `await tab.screenshot()`。
- 表单提交、发布、后台写操作必须先获得用户明确授权；授权弹窗按“仅这次 / 本会话 / 拒绝”如实选择，不绕过、不代答。
