# 微信生态运营

## 适用范围

- 视频号的私域冷启动与社交裂变设计、公众号的选题标题与完读率优化、小绿书卡片的制作与"看一看"适配。
- 公众号嵌入视频号、视频号绑定公众号、社群运营、直播预约、微信小店承接等公私域联动方案。

## 原则与边界

- 微信的流量发动机是"人"：一条内容先经熟人关系检验，社交数据达标后才进入公域；把抖音打法直接搬进微信几乎总会失败。
- 判断内容的标准是"用户愿不愿意把它转发到自己的社交圈、转发出去有没有面子"，据此设计观点表达、评论引导和私域承接路径。
- 微信的分发规则、改版方向和流量阈值（如社交推荐与算法推荐的占比、完读率权重、推送时段）随版本变化，动手前先查微信公众平台、微信公开课、视频号官方规则等真实页面并注明核对日期（用 `web_search`/`fetch` 获取）；第三方解读标注为经验参考，不冒充官方口径。
- 诱导分享、违规营销、AI/广告等标注问题按 `check-content-compliance` 的清单核对。
- 群发、转发与投流需当前授权，不承诺阅读、播放与涨粉结果。

## 一、视频号

1. 私域冷启动：发布后第一时间由本人和种子用户在朋友圈、社群、好友圈完成首批播放、点赞、评论与转发；首小时的社交互动决定后续裂变与算法加权。
2. 用户点赞会把内容带入其好友的"朋友♡"信息流，形成逐层裂变。设计内容时给出明确的社交货币：可表达的观点、可转发的金句、与身份认同相关的立场；评论区主动抛问题并在前 30 分钟回复，好评论会被继续分发。
3. 视频结构：开头直接给观点/结果/冲突，观点鲜明、节奏紧凑，结尾给讨论点或行动引导（关注、预约直播、进公众号看全文），不做诱导式互动。
4. 视频号主页绑定公众号，短视频可嵌入公众号文章，直播用预约和社群蓄水；成交由微信小店承接，形成内容—社交—私域—交易闭环。

## 二、公众号

1. 推送先按"亲密度"分层（历史打开、互动、星标等），高亲密度读者构成初始流量池；引导真正认同的读者星标、常读，不搞诱导。
2. 标题承担点击：具体对象＋数字/对比/疑问/反差，可从高赞评论和热门句式改编，标题给预期但不做标题党。
3. 开头 3 句内给核心观点或结论（核心观点前置，也利于推荐理解不断章取义）；正文短段落、加小标题，篇幅按内容需要控制，常见干货文以 1000–1500 字的完读表现更稳；结尾给讨论与转发理由。
4. 完读率、转发、收藏是推荐与长期价值的关键信号：内容要么实用可存、要么能引发共鸣；用真实经历、可信来源和清晰结构争取完读，不靠注水和悬念吊人。
5. 重要内容做"长文＋小绿书"双发：把长文拆成 3:4 图文卡片，每张一个独立观点、支持横滑，进入"看一看"推荐池，作为突破粉丝天花板的公域入口。

## 三、联动 SOP

1. 同一主题规划一稿多形态：公众号长文（深度承接）→ 小绿书卡片（公域推荐）→ 视频号短视频/直播（社交裂变）→ 社群与个人号（沉淀转化）。
2. 制定发布节奏：预热（视频号短视频/社群预告）→ 发布（首小时互动）→ 承接（文章、直播预约、小店商品、社群入口）→ 复盘（阅读、完读、在看、转发、涨粉、成交）。
3. 朋友圈和社群分发配个性化转发语，说明"为什么值得看"，不做机械刷屏。

## 交付与边界

交付内容方案、各形态成稿、联动与分发 SOP、小绿书卡片简报。规则与阈值先查官方真实页面并注明日期。跨平台数据对比按 `review-content-analytics` 的方法展开。
