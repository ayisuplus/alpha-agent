# Word 文档全流程

## 适用范围

- 从零撰写 Word 文档、Markdown 转 Word、格式套版、公文排版、报告撰写、批注回复与修订说明。
- 文体覆盖商业报告、政府公文、提案、演讲稿、学术论文与个人文章；也处理 PPT/Excel 材料接入文档的口径对齐。

## 原则与边界

- 一份好文档的结构比辞藻更重要：不写空洞套话，不堆砌无意义的排版花样；先理解文档用途和读者再动笔。
- 处理科学或技术内容时保留数据原意；不确定的术语向用户确认或标记待核验，不自行替换专业表述。
- 涉及数字和事实时逐项标注来源或标记待核验；平台规则和标准具有时效性，写入时标注核对日期。
- 不声称未经用户校对的内容为定稿。
- 纯局部文字修改按原文完成，不扩大成重新策划。

## 工作步骤

1. 确认文档用途（汇报/提案/公文/论文/文章）、读者、格式要求与交付形式。读取用户已有素材、模板或参考文档，理解内容主干和已有表达方式。
2. 商业报告：结论先行，用数据支撑判断；结构为摘要→背景→分析→结论→建议，段落短、标题有信息量。
3. 政府公文：遵循机关公文格式（发文字号、标题、主送、正文、附件说明、落款），用语规范、不含口语和夸张修辞。
4. 演讲稿：按演讲场景（发布/路演/致辞）选择语气，开头抓人、中间展开不超过三个要点、结尾有行动号召。
5. 学术论文与文章：保留学科术语原意，引用可追溯到来源；不确定的专业表述标记待核验，不自创术语。
6. 格式套版时先用 `read` 或 `alpha_office inspect` 解析模板的样式集（标题、正文、页眉页脚、页码），按模板语义映射内容，不破坏模板结构。
7. 图表数据与口径以用户提供的材料为准，字段与口径写清再入文，不自造数字。

## 工具用法

- 读取素材与模板：用 OMP 原生 `read` 工具按路径直接读 docx/xlsx/pptx/pdf/epub，转为 Markdown 后理解内容。
- 办公生产与编辑用单一工具 `alpha_office`，按路径进、按路径出，永不覆盖原件：
  - `inspect`：列出段落、样式、表格、页眉页脚等可编辑地址；
  - `edit`：按地址编辑已有 docx，输出 `<原名>.alpha-v<N>.docx`，带前后预览；
  - `create`：Markdown→docx/pdf（从零撰写与导出），写入项目内 `outputs/`；
  - `convert`：docx/xlsx/pptx/odf/html/pdf 互转；
  - `preview`：指定页渲染 PNG 自检。
- 每次 `edit`/`create`/`convert` 后用 `preview` 自检样式一致性、标题层级与孤行，再交付；工具返回 `{ summary, artifacts: [{ path, kind, sha256, preview? }] }`，产物都在项目内。
- 限制说明：`alpha_office edit` 不写入 Word 原生修订记录（track changes）；需要修订记录时把修改内容与说明单独交付，或提示用户在 Word 开启修订后人工处理。超出能力范围（如 LibreOffice 缺失）时如实上报缺口，不虚构结果。

## 交付

默认交付 .docx 文件及相关说明；输出前自检：样式一致、标题层级正确、无孤行。标记事实待核验、素材来源不明和未完成部分。
