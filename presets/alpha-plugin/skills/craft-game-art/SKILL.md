# 从风格规范到可接入的 2D 资产

## 适用范围

- 风格规范（像素网格基准、调色板、轮廓与光影规则）、资产清单与命名约定、精灵与图集规格（留白与挤压、尺寸上限、锚点、朝向处理）。
- 帧动画与骨骼/切片动画的时间轴与动画事件、瓦片集与场景层（自动瓦片、视差、通行与装饰分层）、UI 皮肤与九宫格、状态与字体可读性、特效的强度与时长预算。
- 与引擎资源管线的对接约定；每份资产都带用途、尺寸、锚点、碰撞盒关系和动画帧表。

## 原则与边界

- 看素材先问三件事：网格是否统一、调色板是否克制、角色在最小显示尺寸下是否还能被一眼读出；规范先于出图，批量资产才不会互相打架。
- 动画是玩法信息的一部分：起手帧、命中帧、可取消窗口要能被程序读到并触发判定与音效；动画好看但判定对不上等于手感坏了。
- 涉及新风格方向时先找真实优质参考，记录来源、查看日期和借鉴维度，不把参考作品的品牌、角色或内容挪作用户产品；未看过图像时不描述其具体设计。
- AI 生成素材用于概念探索与临时占位时必须标注，并规划替换为最终资产；版权、风格一致性与平台规格风险提前说明。
- 分辨率、缩放与图集上限以引擎官方文档或实测为准并注明日期；性能与容量数字以实测为准。
- 不实现游戏逻辑；不凭未看过的参考描述具体设计。

## 一、风格规范

1. 定像素网格基准（角色、场景、UI 使用同一套单位）与最小可读尺寸：角色在基准分辨率下要能被一眼识别，剪影优先于细节。
2. 调色板克制：限制色数，明度分阶明确，前景与背景拉开明度或饱和度差；轮廓与阴影规则写成一句可执行的话（如"统一左上光源、外侧描边一像素"）。
3. 新风格先找真实优质参考，记录来源、查看日期与借鉴维度。

## 二、资产清单与命名

1. 按角色、敌人、道具、瓦片、UI、特效分类列出资产，每项标注用途、尺寸、锚点、与碰撞盒的关系、朝向数量。
2. 命名与目录约定一次定好（用途_对象_状态_方向_序号），让程序可批量加载；动画帧用连续编号并写明帧序。

## 三、精灵、图集与瓦片

1. 图集留白与边缘挤压，避免缩放与采样时相邻帧渗色；图集单张尺寸上限以引擎文档或实测为准并注明日期。
2. 锚点与轴心统一：角色脚底或中心、武器挂点、UI 九宫格切点都要在规范里写明。
3. 瓦片集与自动瓦片边界规则一次定清，通行层与装饰层分离；视差层写明层数与速度，避免遮挡可玩区域。

## 四、动画与事件

1. 帧动画给出帧数、每帧时长、循环点与状态清单（待机、移动、起手、命中、受击、死亡）；骨骼或切片动画给出骨架约束与切片命名。
2. 动画事件与判定对齐：命中帧、可取消窗口、生成物出现帧、音效与粒子触发帧写进帧表，供程序读取。
3. 状态过渡与混合写明条件与时长；打断优先级明确（受击 > 攻击 > 移动），避免出现卡在中间状态。

## 五、UI 皮肤与特效

1. UI 用九宫格与统一间距，逐个列出 normal、hover、pressed、disabled、focus 状态；不只用颜色表达状态。
2. 字体在最小分辨率下的可读性优先，点阵字体需确认字号与字重可用；提供缩放与高对比选项。
3. 特效按反馈契约控制强度与时长：粒子数量、屏幕闪白、镜头震动都要有上限与可关闭项，且不遮挡玩家必须看到的信息。

## 工具用法

- 读取设计文档与参考素材：用 OMP 原生 `read` 工具按路径直接读 docx/xlsx/pptx/pdf/epub，转为 Markdown 后理解内容。
- 概念图与占位素材用媒体生成工具 `alpha_generate_image`，产出写到 `outputs/media/<可读名>.<扩展名>`；ComfyUI 服务不可用时上报缺口，不代替用户启动服务。生成素材只作概念与占位，必须标注并规划替换。
- 规格交付：风格规范、资产清单、帧表与事件表用 Markdown 交付，或用 `alpha_office create`（Markdown→docx/pdf）写入项目内 `outputs/`，交付后用 `preview` 自检。
- 限制说明：精灵图集打包、骨骼绑定与引擎导入由所用引擎的资源管线完成，不在本机工具能力内；规格按引擎文档写清，接入问题如实上报缺口。

## 六、交付与验收

交付风格规范、资产清单与命名约定、图集与瓦片规格、动画帧表与事件表、UI 皮肤与状态规范，以及在实际分辨率与缩放下的检查方法。验收看：规格能被程序直接接上、动画事件与判定对齐、AI 生成占位均已标注替换计划。玩法与反馈契约来自 `design-game-systems` 的设计，实际分辨率与手感由试玩验证核对。
