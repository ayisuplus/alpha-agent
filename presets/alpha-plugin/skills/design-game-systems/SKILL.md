# 从概念到可玩的系统设计

## 适用范围

- 核心循环与机制清单、机制优先级与最小可玩切片、数值与经济系统（产出、消耗、时间常数、随机与保底）。
- 关卡结构与难度曲线、新手教学与无文字引导、反馈契约（输入延迟预算、命中停顿、镜头震动、音效触发点、容错窗口）。
- 退化策略与风险清单、可玩性验证清单；每个机制写成有触发条件、规则和可观测结果的条目，每个数值带来源与待验证标记。

## 原则与边界

- 判断玩法先问"玩家每隔几十秒在重复什么、这一轮重复比上一轮多了哪个选择"，而不是先问题材、画面和剧情。
- 先做最小可玩切片：核心循环没被真人或自动化试玩验证之前，不扩张内容量、不堆系统、不要求精细美术。
- 数值是手感的一部分：一个动作爽不爽由帧数、判定窗口、奖惩曲线和失败宽容度共同决定；设计前先想清楚"玩家会怎么把这套系统玩坏"。
- 引擎能力、API 行为和性能数字查官方文档或实测，注明核对日期与目标平台；参考玩法记录来源与借鉴维度，不把他人的 IP、美术素材或关卡照搬进用户产品。
- 试玩验证之前所有数值都是待验证初值；不承诺"好玩"、留存、评分或收入。
- 不实现代码，不定美术风格。

## 一、核心循环

1. 用一句话写清玩家反复做的事：输入 → 反馈 → 奖惩 → 进度 → 新的选择，并说明这一轮比上一轮多了什么选择。给出循环图（文本即可）。
2. 循环节奏以秒计：一个循环的时长、一次反馈的间隔、一段紧张与放松的配比。参考同类游戏先记录来源，再决定自己要快还是慢。
3. 列出核心机制清单并排序：只保留支撑循环的 2–4 个机制进入最小可玩切片，其余列为后续候选并写清依赖。

## 二、数值与经济

1. 资源表：每种资源的来源、消耗、上限、恢复速度与时间常数；产出与消耗要能对账（一段时间内的理论收支表）。
2. 公式与成长：伤害/分数/掉落等用显式公式写清，标明取整、上限与边界（零值、负数、溢出）。先给初值，标注"待试玩校准"。
3. 随机与保底：随机项写明分布、期望值与保底规则；玩家能感知的随机必须有可控期望，避免长期运气决定成败。
4. 列出会引发通胀或通缩的回路（可无限刷的资源、随时间贬值的奖励），并给出反制。

## 三、关卡结构与难度曲线

1. 难度靠变化而非单纯加数值：新敌人组合、新地形约束、新时间压力、资源受限交替出现；写清每段引入什么、练习什么、何时组合。
2. 每关给出目标时长、失败点预期、检查点与重试成本；重试成本过高会放大挫败，过低会削弱选择。
3. 教学：优先无文字示范与可跳过提示，第一次出现的关键机制要有安全练习场景；写清教学触发与完成条件。

## 四、手感与反馈契约

1. 给出输入延迟预算、命中判定窗口、容错设计（土狼时间、输入缓冲、跳跃可变高度）的具体数值，供程序实现。
2. 逐条列出反馈的触发点与强度上限：命中停顿帧数、镜头震动幅度与衰减、粒子数量、音效触发帧、屏幕闪白时长；强度要能关闭或降低（无障碍）。
3. 明确失败的可解释性：玩家失败后应能看到原因，避免"看不懂的失败"。

## 五、风险、退化与验证清单

1. 退化策略：玩家能找到的刷分、无脑重复、跳过内容的最优解；逐条给出反制（收益递减、条件限制、目标多样化）。
2. 阻断性风险：卡关、无解状态、软锁、存档损坏、多人不同步；逐条给出预防与兜底。
3. 验证清单：把"好玩"换成可观测信号（通关率、单局时长、死亡点分布、机制使用率），交由试玩验证实测，设计阶段不自行宣布达标。

## 交付与验收

交付核心循环图、机制清单与优先级、数值表与公式、关卡结构与难度曲线、教学与反馈契约、风险与退化策略清单、可玩性验证清单。验收看：每个机制可被实现和被测、每个数值有来源与待验证标记、验证清单的信号可观测。实现按 `implement-gameplay` 的方法继续，美术规格按 `craft-game-art` 的方法继续；涉及游戏内界面流程与可访问性时对接 `design-interface` 的规范。
