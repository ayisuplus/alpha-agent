# 从真实参考到音画交付

## 适用范围

- 参考板、资产约束、分镜、图像提示、模型生成包和音画节奏；交付时区分方案、已生成素材、技术检查和人工视觉/听觉验收。
- 输入是当前剧本/简报、原始角色与品牌资产及可用工具清单；将真实参考里的视觉方法转成可执行方案，不靠堆风格词创造"质感"。

## 原则与边界

- 涉及审美先查看真实优质素材，记录来源和借鉴范围；不要编造看过的参考。
- 原始角色与品牌资料决定身份，参考样张只约束明确指定的构图或材质；样片不能自动重定义主体。
- 只处理已授权的对象，不擅自生成新角色或改变故事；剧情变更由用户确认后调整方案。
- 只有当前实际可用的工具才能进入执行方案；指定服务不可用时报告缺口。提示文本不是生成结果；不把一个成功帧当成整段视频成功。

## 视觉与镜头

1. 给每份参考注明用途：身份、服装、构图、光线、材质、运动或声音。
2. 建立当前交付必需的资产约束：比例、色彩、识别特征、环境与连续性。
3. 将场景映射为稳定镜头编号，写明叙事目的、主体动作、景别、机位/运动、时长、声音和转场。说明每个镜头依赖哪份资产与剧本版本。
4. 生成包对应一次真实调用：模型/服务、工作流版本、输入文件、尺寸、时长、提示和约束。
5. 同时规划环境声、音乐、对白与节奏；先确认授权素材和现有音轨，再安排同步点。

## 工具用法

- 读取剧本、简报与参考素材：用 OMP 原生 `read` 工具按路径直接读 docx/xlsx/pptx/pdf/epub，转为 Markdown 后理解内容；找参考与核对来源用 `web_search`/`fetch`，需要查看实际页面时用 OMP 原生 `browser`（需用户授权，可访问本机开发服务器）。
- 媒体生成用 `alpha_generate_image` / `alpha_generate_voice` / `alpha_generate_video`，一次生成包对应一次真实调用；产出写到 `outputs/media/<可读名>.<扩展名>`，或写到用户指定的位置。
- ComfyUI 服务不可用时上报缺口，不代替用户启动服务，不以其他流程偷偷替代；每个产物记录文件路径、尺寸/时长与校验信息。
- 方案与分镜表用 Markdown 交付，或用 `alpha_office create`（Markdown→docx/pdf）写入项目内 `outputs/`，之后用 `preview` 自检排版。工具返回 `{ summary, artifacts: [{ path, kind, sha256, preview? }] }`。

## 验收与交付

- 图像检查身份、手部/结构、服饰、文字和画面边缘。视频检查首中尾及关键运动段的形变、闪烁、连续性和音画同步；需要确认声音时实际听取。
- 文件存在、分辨率正确和视觉/听觉可用分开记录；交付索引连接场景、镜头、输入资产、模型调用与输出文件，保留候选和拒绝理由。
- 没有可用生成服务时交付方案及缺口，不宣称已生成或已验收。
