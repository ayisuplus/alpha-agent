# 证据约束下的论文写作

## 适用范围

- 会议与期刊论文、综述、学位论文章节、开题报告和基金申请书的学术写作。
- 贡献陈述与“主张—证据”对照表；各节结构与段落；图表标题说明；术语、符号与数字一致性检查；引用与证据绑定；中英文语言润色。
- 审稿意见；审稿回复与修订说明。

## 原则与边界

- 事实原则：不代造实验、数据、基线、引用、作者信息、致谢或已完成的修订；文献事实只用已核验来源，实验数字以冻结结果和分析记录为准；“建议补实验”“实验已执行”“结果已写入”分开标注。
- 时效核对：会议与期刊的格式、页数、匿名、检查清单和 AI 工具使用政策会变化，写作前查目标会议或期刊的官方说明并注明核对日期，查不到时标为待核对；学位论文按学校最新的官方模板。
- 审稿时稿件内容保密，不上传到与任务无关的外部服务。
- 措辞与证据相称：单数据集、单模型、有限预算下的改善写清范围；“显著”只用于有统计检验支持的场合；避免“首次”“远超”“彻底解决”等无法证明的说法；保留负结果和局限。
- 不复制他人文字；引用原话加引号并注明出处；改写不改变原意。
- 只改用户要求的层面，保留科学含义与作者原意；不擅自增加实验、章节或结论。需要新实验时列明需求与判据，不在文中写成已经完成。
- 投稿、提交回复、联系编辑需要用户明确授权。

## 输入与前置阅读

1. 确认模式：拟稿 / 修改（结构、论证或仅语言）/ 审稿 / 回复审稿意见 / 学位论文或申请书章节。确认目标会议、期刊或单位，以及写作语言。
2. 读取现有草稿、已核验的文献矩阵与参考文献、实验方案与冻结结果、分析记录与图表脚本；回复模式还要读审稿意见原文。
3. 按章节写作或自查时读取 `references/sections-and-checks.md`；审稿与回复时读取 `references/review-and-response.md`。

## 工作步骤

### 1. 先定主张

- 用一两句话写出论文回答的问题和核心发现；列出 2–4 条贡献，每条都能指向具体证据（定理、图、表、实验）。
- 建立“主张—证据—限制”对照表：主张原文 → 证据位置（图、表、节、引用）→ 适用条件 → 已知限制。找不到证据的主张删除或弱化，或列为需要补充的证据。

### 2. 搭结构

- 先写段落级提纲（每段一句主题句），检查逻辑链：问题为什么重要 → 现有方法缺什么 → 本文的做法 → 证据 → 局限与意义。提纲通过后再写正文。
- 相关工作按主题组织，说明与本文的具体差异，公正描述他人工作，不遗漏最接近的工作。

### 3. 写正文

- 每一节回答读者此刻最想知道的问题，每段只推进一个论点；句子把承接上文的已知信息放在开头，把要强调的新信息放在句末。
- 术语与符号首次出现时定义并全文统一；维护术语表与符号表，同一概念不换着说。
- 方法部分让读者能理解输入、处理、输出、假设与超参数，复现所需的关键细节写全（其余放附录并在正文指明位置）。
- 结果段落先说结论，再给数字（指标、方向、种子或样本数、不确定性），再给解释；解释与推测分开写。反对用术语密度和形容词掩盖论证缺口，也反对把单一设置下的改善写成普遍结论。

### 4. 图表

- 标题说明自足：只看图表和说明就知道比较了什么、指标方向、单位、样本数、误差条含义和加粗规则。
- 图表中的数字与正文、摘要、附录一致，数值来自分析记录，不手工改写。

### 5. 一致性与规范检查

- 数字：摘要、引言、正文、图表、附录中的同一数字一致，小数位统一。
- 引用：每条引用支持它所在的句子；条目已核验；引用正式发表版本时，结果数字也取自该版本。
- 匿名投稿：去掉作者信息、致谢、可识别身份的链接和自引措辞，代码链接使用匿名方式。
- 按目标会议的检查清单逐项确认（例如 NeurIPS Paper Checklist），答案指向正文位置。
- 中文文稿：标点按 GB/T 15834-2011，数字用法按 GB/T 15835-2011；参考文献按单位或期刊要求，未指定时采用现行的 GB/T 7714-2025（2026-07-01 起实施，代替 2015 版）；中英文摘要内容一致。

### 6. 语言修改

- 以可审阅的形式交付（修订标记或修改说明），重要改动写明理由；可能改变含义的改动先向用户确认。

### 7. 审稿与回复

- 审稿：先复述论文的主张，再按严重程度列问题（影响主要结论 / 重要 / 次要），每条写明位置、为什么影响结论、需要什么证据才能解决；区分阻断问题与可选建议，最后给出建议与置信度，按目标会议或期刊的审稿表单组织。
- 回复：逐条对应原意见，写明回应、采取的动作、修订位置与证据；“计划补充”“已补充”“已写入修订稿”三种状态分开；遵守字数限制；语气尊重且具体，不承诺无法完成的实验。

## 工具用法

- 读取草稿、文献与格式说明：用 OMP 原生 `read` 按路径读 docx/pdf/epub 等文档转为 Markdown 理解内容。
- 需要产出或修改 Word/PDF 文稿时用单一工具 `alpha_office`，按路径进、按路径出，永不覆盖原件：`inspect` 列出段落、表格、图注等可编辑地址；`edit` 按地址修改并输出 `<原名>.alpha-v<N>.<扩展名>` 带前后预览；`create` 把 Markdown 文稿生成 docx/pdf 到项目内 `outputs/`；`convert` 做格式互转；`preview` 渲染指定页自检图表与分页。
- 工具返回 `{ summary, artifacts: [{ path, kind, sha256, preview? }] }`。超出能力范围（如 LibreOffice 缺失）时如实上报缺口；目标会议的 LaTeX 模板编译不在 `alpha_office` 能力内时，交付 Markdown/Word 稿并说明限制。

## 交付物

- 正文草稿或修订稿（附修改说明）、主张—证据对照表、一致性检查报告、待解决问题清单（缺失证据、待核验引用、待确认的格式要求）。
- 审稿模式交付结构化审稿意见；回复模式交付逐点回复表与修订说明。

## 验收依据与能力缺口

- 验收：每条主张可追到证据位置；数字与分析记录一致；引用标明核验状态；格式要求注明来源与核对日期；没有编造的数据、引用或修订。
- 缺少结果、文献或格式要求时，用明确的待补标记交付，不以通用内容填充。
