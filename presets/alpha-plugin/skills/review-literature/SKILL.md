# 从检索线索到可引用证据

## 适用范围

- 把研究问题拆成可检索的概念与同义词；多渠道检索与引用追溯（向前、向后滚雪球）；版本合并（预印本、会议版、期刊版、勘误与撤稿）。
- 精读与证据抽取；方法与实验条件对比；证据矩阵、分类框架和带检索范围限定的研究空白。
- 参考文献条目核验与“引用—命题”一致性检查。重点服务 AI 与计算机科研，也能按需要切换到其他学科的数据库与引用习惯。
- 按规模区分快速调研、结构化综述和系统综述；只有用户要求且资源允许时才按系统综述流程保留完整的筛选记录。

## 原则与边界

- 事实原则：参考文献只能来自本次会话实际检索到或用户提供的记录，绝不凭记忆写出标题、作者、年份、DOI 或页码；没有读到全文就不写原文细节。
- 四个状态分清、不让前一个冒充后一个：检索命中 → 摘要线索 → 已读全文 → 已核验结论。
- “没有搜到”只说明检索范围内未发现，不证明首创；排行榜和聚合站只作线索，数字要回到原文核对条件。
- 数据库的覆盖范围、接口和访问限制会变化，以实际访问结果为准。
- 同样重视反例、负结果和复现失败的报告；不把快速调研包装成系统综述。
- 检索、网页与 PDF 读取能力不可用时先上报缺口，不虚构检索结果；不自动启用付费检索或与任务无关的服务；时间或检索预算用尽时停止扩展并报告已覆盖范围。

## 输入与前置阅读

1. 确认交付类型与规模：快速调研（方向与关键文献）、结构化综述（分类框架与对比）、系统综述（可复现的筛选流程，仅在用户要求时）、引用核验（检查已有参考文献）、Related Work 素材。规模决定检索深度。
2. 确认研究问题、时间范围、学科与语种、必须包含或排除的工作，以及用户已给的论文和草稿。用户给定的论文先读，再从它扩展。
3. 检查本轮可用的检索、网页读取与 PDF 读取能力，缺失时如实说明能做到哪一步，不自动要求付费服务。
4. 需要各渠道的用途与陷阱、版本与撤稿核验、条目核验清单或系统综述流程时，读取 `references/sources-and-verification.md`。

## 工作步骤

### 1. 拆解问题与制定检索式

- 把问题拆成四类概念：任务或问题、方法族、数据与评测场景、约束（规模、预算、领域）。每类列出同义词、缩写、旧称和中英文说法，例如 in-context learning 与 few-shot prompting。
- 为每个渠道写出实际使用的查询串，记录渠道、查询、日期、结果数和筛选理由。这份检索日志是交付的一部分，别人照着能复现。

### 2. 多渠道检索与引用追溯

- 至少组合两类渠道：学术搜索与引用图谱（如 Semantic Scholar、OpenAlex、Google Scholar），以及学科文库或书目库（如 arXiv、ACL Anthology、DBLP、OpenReview、出版社数字图书馆）。
- 从 3–5 篇高度相关的种子论文出发，做向后追溯（它引用了谁）和向前追溯（谁引用了它），直到新增结果基本都是已见工作；记录每轮新增数量。
- 主动检索反例与负结果：加入 limitations、revisiting、reproducibility、fails to 等词，并查找对同一方法的复现或质疑论文。

### 3. 筛选与版本合并

- 先按标题和摘要筛，再按全文筛，每篇写一句纳入或排除理由（范围不符、没有实验、重复版本等）。
- 同一工作的 arXiv 多个版本、会议版、期刊扩展版和勘误合并为一条，注明引用哪个版本以及版本间的结果差异；检查撤稿、撤回和勘误声明。
- 区分发表状态：同行评审的期刊或会议、workshop、仅预印本、技术报告或博客。状态影响证据强度，但不等于正确。

### 4. 精读与证据抽取

- 只精读与问题相关的部分：问题设定、方法关键步骤、实验设置、主结果、消融和局限。每条抽取记录页码、章节、表号或图号。
- 实验类结论同时抽取条件：训练数据与规模、模型与参数量、推理预算（采样次数、上下文长度、工具使用）、数据划分、评测协议（零样本或少样本、提示模板、解码参数、指标定义与方向）、基线是复现还是抄录、是否报告种子数与方差、代码与数据是否公开。
- 注意大模型研究特有的风险：测试数据可能进入预训练语料（基准污染）、闭源模型在同一名称下更新、评测脚本差异、以模型作为评判者带来的偏差。
- 读不到全文（付费墙、链接失效）时，只报告实际看到的内容并标“未读全文”，不从摘要推断细节。

### 5. 比较与综合

- 条件不一致时不直接比较数字；确实需要并列时，列出差异并说明差异可能影响的方向。
- 按问题设定、方法假设或技术路线建立分类框架（不按年份罗列），写清每一类的核心思想、代表工作、适用条件和已知弱点。
- 给关键命题标证据强度：多个独立团队在不同设置下一致支持 / 单一来源或单一设置 / 结果相互矛盾 / 只有主张没有实验。
- 研究空白写成：“在检索范围 X（渠道、时间、查询）内，未发现同时满足 A 与 B 的工作；最接近的是 C，差异在于 D。”它是待验证的候选，不是首创声明。

### 6. 条目与引用核验

- 每条参考文献用原始记录核对标题、全部作者及顺序、年份、发表处、卷期页码或文章号、DOI 或 arXiv 编号；以出版方页面、DOI 解析结果和 DBLP、ACL Anthology 等书目记录为准，搜索引擎摘要不算核验。
- 检查“引用—命题”一致：被引文献确实支持正文里那句话；综述或二手转述的结论回到一手来源；不用文献 A 支撑 A 没说过的话。
- 条目状态分四级：已核验 / 部分核验（写明缺哪项）/ 未核验 / 信息冲突或疑似不存在。未核验的条目不能以已验证的身份交给写作者。

## 交付物

- 检索日志：渠道、查询、日期、结果数、纳入与排除计数。
- 证据矩阵，每行一个命题或一篇论文：命题 → 来源与原文定位 → 方法、数据、预算与评测条件 → 支持、反对或限定 → 局限 → 证据强度 → 核验状态。
- 分类框架与综合结论，分清“文献已报告”“我的综合判断”“待验证假设”三种表述。
- 参考文献列表（BibTeX 或用户要求的格式），每条附核验状态；中文文献格式按用户或目标单位要求，没有要求时说明采用的规范。
- 未解问题清单：可检验的差异线索、可引用命题与适用边界，供实验设计与论文写作环节取用。

## 验收依据与能力缺口

- 验收：任何一条引用都能从矩阵追到原文页码或表号；检索可按日志复现；条件不一致的比较都有说明；研究空白都带检索范围；没有凭记忆写出的条目。
- 检索、网页或 PDF 读取不可用，或关键全文无法访问时：交付已完成部分，列出缺口和需要用户提供的材料（PDF、数据库权限），不以记忆补全。
