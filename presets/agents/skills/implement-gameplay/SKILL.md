# 从设计到可运行的 2D 玩法

读取项目结构、已定引擎或框架、构建与检查命令、资源目录和系统设计文档。引擎未定时先与用户确认选型再动手，不擅自引入依赖或改技术栈。

## 一、时间与主循环

1. 固定步长推进逻辑、可变步长渲染，并对渲染做插值；对 delta 设上限，切后台或断点恢复后不发生一次大跳。
2. 暂停、失焦、标签页隐藏要有统一的时间与输入处理：计时停止、音频静音或暂停、输入状态清空，恢复后不残留按键。
3. 随机使用可注入的种子，便于试玩复现缺陷。

## 二、状态与数据

1. 用显式状态机管理菜单、加载、游玩、暂停、结算与失败；状态切换只走一处入口，切换时清理属于旧状态的监听、定时器与输入。
2. 单一数据来源：权威状态只有一份，派生值从它计算；UI 与逻辑读同一份，避免两边不同步。
3. 存档写明版本字段与迁移路径，损坏时给出可恢复的降级行为而不是崩溃。

## 三、实体、碰撞与手感

1. 优先组合式/数据驱动组织实体，不为赶功能建深继承链；高频生成物用对象池复用。
2. 按玩法选碰撞方案：轴对齐盒、圆、网格或瓦片；先宽相再窄相。高速位移用扫掠或限制单步位移，避免穿透。
3. 手感优先的自定义运动与通用物理分开处理，别混用两套坐标系；土狼时间、输入缓冲、可变跳跃高度按设计契约实现，参数集中可调。
4. 判定与动画对齐：伤害、命中停顿、音效由动画事件或明确帧号触发，不用猜测的时长。

## 四、输入与相机

1. 键鼠、手柄、触屏走同一层抽象，支持重绑定；同时按键与快速连点要有确定行为。
2. 相机跟随写明死区、边界、平滑与像素对齐规则；镜头震动与停顿不破坏输入判定。

## 五、资源、渲染与性能

1. 图集打包、批处理与剔除按引擎能力落实；图集尺寸与纹理上限以引擎文档或实测为准。
2. 分辨率与安全区自适应：世界层与 UI 层分开缩放，UI 不被拉伸变形；小屏与窗口极端尺寸下关键操作仍可达。
3. 避免每帧分配与每帧查找；按目标帧率分配帧预算（逻辑、渲染、垃圾回收），用剖析工具定位，不凭感觉优化。
4. 音频按事件触发并限制并发，分组管理音量，加载失败要能降级不阻断。

## 六、验收与交接

1. 修复逻辑缺陷先复现（固定种子或最小场景），再做最小修改，并说明不会引入新的状态不一致。
2. 实际运行游戏并操作目标路径：能进入、能完成一个完整循环、能存档读档、状态切换正确。浏览器可用时实际操作并记录结果与错误信息。
3. 性能结论写明设备、分辨率、运行时版本、采样时长与场景，给出帧时间分布而不只给平均值。构建通过、截图或 DOM 检查都不能证明可玩与跟手。

交付可运行的变更、复现步骤、执行命令与实测数据、未验项。缺失的美术与音频资产上报缺口，不用占位素材冒充成品；接口或引擎能力不明确时给出真实调用位置和所需契约，不虚构 API。
