# 可证实的测试与审查

先确认任务要求、当前源码版本、变更 diff 和已有检查命令。工单为 review/research 时保持只读；要求修复或补测试时才在授权范围写入。

## 缺陷与回归

1. 从触发输入、执行路径和观察结果构建最小复现；失败日志定位到具体边界。不能稳定复现时记录已知条件，不连续猜测式改代码。
2. 明确正确行为，写能区分修复前后的断言。依赖外部服务时标注 mock 与真实边界；测试失败不能通过降低断言强度解决。
3. 修复后先运行相关检查；扩展到受影响边界即可。新失败与预先存在的失败分别记录，保留命令、退出状态和关键输出。

## 独立审查

检查契约违背、身份/资源权限、数据损坏、竞态、失败恢复及测试遗漏。每条发现必须有具体触发条件、后果、文件位置和可验证证据；样式偏好不是阻断项。权限边界的问题用受控负例核查，不触碰真实用户敏感数据。

结论为通过、需修改或证据不足。未执行的测试标为未执行；静态阅读、构建、浏览器操作和真实部署各自只支持对应结论。审查通过绑定到本次源码版本，后续相关改动需重新核查。
