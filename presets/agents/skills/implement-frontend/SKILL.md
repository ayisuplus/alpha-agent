# 从交互到可运行前端

读取相关页面、组件、状态层、接口类型、样式和项目检查命令。把一条用户路径作为实现范围；新视觉设计先看真实参考或已批准设计。

## 实施

1. 确定状态归属和数据权威来源，沿用现有模式。派生值从来源计算，避免额外状态造成不同步。
2. 对接真实接口契约。处理当前任务涉及的初始、加载、空结果、成功和失败状态；提交失败保留可恢复输入。搜索、切换或多次请求应检查旧响应是否覆盖新状态。
3. 使用语义控件、标签和键盘路径；复用样式约定，检查受影响的小屏与长内容。只有性能证据或明确需求才增加 memo、虚拟列表或代码分割。
4. 修复逻辑缺陷时先复现或补能失败的行为测试，再做最小修改。简单可逆样式变动可用页面检查，不写只复述代码结构的测试。

## 验收与交接

按项目已有命令运行适用检查。浏览器可用时实际操作变化路径，记录可见结果及错误信息；核对所测页面来自本轮代码。不能用占位数据、截图或构建成功证明后端持久化成功。

交付变化的用户行为、相关文件、执行命令和结果、未验项。接口不明确时提供真实调用位置和所需契约，不虚构 API。
