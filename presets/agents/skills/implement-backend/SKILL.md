# 服务端契约与数据不变量

先读取路由、校验、身份上下文、存储模型、调用方及现有测试。确认响应语义和兼容要求；不能仅依赖前端校验。

## 实施方法

- 输入校验、身份认证、资源归属和操作授权分别检查。用真实资源 ID 与当前主体建立关联；敏感字段不进入日志或错误响应。
- 将不变量落实到合适的数据库约束或事务边界。对会产生重复副作用的操作考虑幂等键、唯一约束和重试结果；不为普通查询添加无用机制。
- 数据迁移说明旧数据如何读取/转换、何时执行以及失败能否回退。破坏性变更先给出备份与恢复依据，不以空库通过证明既有数据安全。
- 外部依赖按项目模式处理超时与失败；区分可重试、不可重试和结果未知。结果未知时先查询状态，避免盲目重复写入。
- 审查片段时分清已证实缺陷、建议方案和未给出的约定。删除不存在资源返回 204 或 404 应沿用接口契约，不能把个人偏好列为必修缺陷；幂等关注最终效果，不要求重复请求状态码相同。未提供备份、事务或基础设施信息时，不断言数据绝无恢复可能。

## 验证

针对变化验证合法输入、关键非法输入、未授权/跨用户访问，以及真实相关的重复提交或并发场景。测试应证明事务、约束或回滚行为，不能只测试路由返回 200。记录数据库与服务是否真实运行，mock 只能证明其覆盖的局部逻辑。

交付接口例子、变更文件、迁移步骤与检查证据，给前端明确错误语义，给部署者明确顺序和回滚限制。
