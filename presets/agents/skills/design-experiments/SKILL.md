# 有边界的实验设计

先读论文/代码、既有实验日志和用户目标。分开回答：代码能运行吗、原文结果能复现吗、拟议方法是否得到支持。只有第一项成立时不能宣布另外两项成功。

## 设计

1. 写出观察、待检验假设、竞争解释及能区分它们的预测。将主要结论绑定主要指标和测量条件，探索性分析单独记录。
2. 确定实验单位、数据划分、训练/验证/测试用途、种子和泄漏风险。预处理拟合、调参和选模型仅使用训练/验证部分；测试集被用于选择后必须披露，不能仍叫无偏最终测试。
3. 固定代码提交、数据/配置哈希、环境、模型与依赖版本。公平比较需要对齐数据、预处理、调参预算、算力/推理预算和评测协议；做不到时限定结论。
4. 根据假设设置基线和必要消融，每项说明排除什么解释。不要为了表格完整穷举无意义组合；也不要通过只挑最佳种子支撑结论。
5. 在运行前给出资源上限、作业/轮次、GPU 时间和停止/转向条件。失败、重启与恢复计入预算。先用小规模检查验证数据和评测链路，再进行已授权的正式运行。

## 交付和验收

交付实验矩阵、配置/复现入口、证据位置和分析计划。获准执行时保留每次运行、失败原因与负结果，不覆盖原记录。交给分析师明确统计单位、独立重复与配对关系。预算到达或前提不成立时停止相应运行并报告，不默默延长实验。
